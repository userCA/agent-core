# 16 — 资源与奖励系统

## 目标

为咪兔提供一套轻量、低打扰、可长期扩展的奖励循环。

这套系统必须同时满足四件事:

1. 让玩家的日常工作和陪伴行为有可见回报
2. 让奖励服务于情感和成长，而不是把咪兔做成数值挂机器
3. 让资源种类足够少，能在网页 / App 里一眼看懂
4. 让黑白、点线、终端风格在奖励层也成立

## 设计原则

| 原则 | 说明 |
|------|------|
| 资源是媒介，不是目的 | 玩家追求的是咪兔的变化，不是囤数字 |
| 奖励先情感，后数值 | 优先给动作、气泡、记忆、外观，再给资源 |
| 终端可读 | 任意奖励结算都应能用 1-3 行文本说清楚 |
| 少种类，高辨识 | 主资源不超过 4 种，避免背包化 |
| 允许错过，不制造焦虑 | 日常奖励可少量错过，但核心成长不被卡死 |
| 防刷而不扫兴 | 高频重复行为收益递减，但不会硬性惩罚 |

## 资源总览

保留 4 类轻资源，分别对应四种玩家感知:

| 资源 | 象征 | 玩家感知 | 核心用途 |
|------|------|---------|---------|
| `snack` | 鱼干 / 零食 | "我在照顾它" | 喂食、安抚、触发专属反应 |
| `spark` | 情绪火花 | "今天有在一起努力" | 解锁角落装饰、线稿特效、轻外观 |
| `memory_shard` | 回忆碎片 | "我们留下了痕迹" | 拼回忆页、纪念卡、相册条目 |
| `ribbon` | 装饰织带 | "这是属于它的东西" | 解锁围巾、项圈、角落摆件、主题边框 |

## 为什么不用金币

终端陪伴养成不适合使用金币、钻石、体力这些通用货币名词。

原因:

- 会立刻把气质拉向手游数值面板
- 不符合咪兔的情感导向
- 很难和黑白、点线世界观统一
- 容易诱导出大量低价值刷取设计

因此所有资源都应带有"关系感"和"世界感"。

## 资源定位

### `snack`

最基础、最亲密的照顾资源。

#### 获取方式

- 完成每日轻目标
- 钓鱼小游戏产出
- 首次安抚 worried 状态成功
- 回归登录补偿
- 某些 breed 专属事件

#### 消耗方式

- `feed` 喂食
- 恢复咪兔的疲惫或坏心情
- 触发稀有喂食反应
- 部分隐藏互动的前置条件

#### 设计定位

`snack` 不应该稀缺到舍不得用，也不应该多到失去存在感。

它的职责是:

- 让玩家顺手照顾咪兔
- 给 `feed` 一个真实成本
- 让"今天喂过它"成为一种微小但稳定的关系动作

### `spark`

代表一起工作、一起努力时产生的情绪火花。

#### 获取方式

- 工具调用成功
- 连锁互动完成
- 每周目标完成
- 里程碑触发
- 特殊时段事件

#### 消耗方式

- 解锁 ASCII 角落房间线稿
- 解锁轻量特效，例如星点、闪烁、边框
- 升级咪兔的休息窝、灯、小挂件
- 解锁品种主题细节

#### 设计定位

`spark` 是工作型玩家的主资源。

它告诉用户:

```text
你不是为了养成而停下工作，
而是在工作途中自然把养成推进了。
```

### `memory_shard`

把散落的经历变成可回看的长期资产。

#### 获取方式

- 周目标完成
- 特殊时间事件，如周年、深夜首次、连续登录
- milestone 奖励
- hidden interaction 首次发现

#### 消耗方式

- 拼出回忆页
- 生成纪念卡
- 解锁成长相册页
- 修复遗失的旧回忆片段

#### 设计定位

`memory_shard` 不能大量掉落。

它的价值来自:

- 稀少
- 长期沉淀
- 能把抽象互动转成可展示收藏

### `ribbon`

最具展示性的装饰资源。

#### 获取方式

- 品种专属 milestone
- 高 bond 阶段奖励
- 稀有事件
- 隐藏互动整链完成
- 周总结中的精选奖励

#### 消耗方式

- 围巾、项圈、蝴蝶结
- 房间挂饰、牌匾、线框边角
- 节日主题样式
- SOULMATE 前的关键视觉装饰

#### 设计定位

`ribbon` 是最慢、最有纪念意义的资源。

它不是日常刷取资源，而是:

- 奖励一次特别的陪伴经历
- 把"养得久"这件事变得可见

## 资源产出层级

同一个资源，不同来源的心理感受不同，因此要分层。

| 层级 | 来源 | 心理感受 | 例子 |
|------|------|---------|------|
| 基础产出 | 提问、工具成功、轻互动 | 稳定、有进展 | `spark +1` |
| 目标产出 | 日目标、周目标 | 被认可、被引导 | `snack +1`, `memory_shard +1` |
| 情境产出 | 深夜相遇、回归、担心后安抚 | 关系真实 | 特殊气泡 + `snack` |
| 纪念产出 | 里程碑、bond 升级、周年 | 值得记住 | `ribbon +1` 或回忆页 |

## 奖励优先级

所有奖励都遵守下面的结算顺序:

1. 角色反馈
2. 收藏反馈
3. 资源反馈
4. 数值反馈

### 1. 角色反馈

优先出现:

- 动作变化
- 表情变化
- 品种口吻气泡
- 称呼变化

示例:

```text
咪兔蹭了蹭你的光标。
"这次真的修好了喵。"
```

### 2. 收藏反馈

其次显示:

- 解锁回忆
- 点亮图鉴
- 获得纪念卡
- 房间线稿新增一角

示例:

```text
[回忆新增] 第一次深夜陪你调试
```

### 3. 资源反馈

最后再显示:

```text
+1 spark
+1 memory_shard
```

### 4. 数值反馈

`bond +x` 应始终排在最末尾，而且尽量弱化视觉权重。

原因:

- bond 是长期结果，不是瞬时爽点
- 玩家应该先觉得它有情绪，再知道它涨了分

## 基础产出公式

### 设计要求

- 好理解
- 可预估
- 允许用户通过自然使用稳定成长
- 不鼓励脚本刷动作

### 建议表

| 行为 | 资源 | 默认产出 | 限制 |
|------|------|---------|------|
| 一次 prompt | 无 / 极低概率 `spark` | 0 或 10% `spark +1` | 防止闲聊刷资源 |
| 一次工具成功 | `spark +1` | 稳定 | 同类工具 10 秒内收益递减 |
| 一次工具失败后成功修复 | `spark +2` | 鼓励恢复 | 每 5 分钟最多触发一次 |
| `/pet` | 无直接资源 | 主要给 bond | 30 秒 CD |
| `feed` | 消耗 `snack` | 不产资源 | 产角色反馈 |
| 完成日目标 | `snack +1` / `spark +1` | 稳定 | 每日结算一次 |
| 完成周目标 | `memory_shard +1~2` | 稀缺 | 每周结算 |
| milestone | `spark` / `memory_shard` / `ribbon` | 一次性 | 不重复 |

## 奖励映射表

### 行为 -> 奖励

| 行为类型 | 首选奖励 | 备选奖励 | 不该给什么 |
|---------|---------|---------|-----------|
| 工作成功 | `spark` | 回忆、品种夸奖 | 大量 `snack` |
| 安抚照顾 | bond、气泡 | 少量 `snack` 补回 | 大量 `spark` |
| 周期目标 | `snack` / `memory_shard` | `spark` | `ribbon` 泛滥 |
| milestone | 回忆页、称呼变化 | `ribbon` | 单纯数字 |
| 稀有事件 | `ribbon` | 特殊外观、图鉴 | 普通 `spark` |

## 目标结算

### 每日目标奖励模板

推荐每个目标只给 1 层资源，完成全部后再给一个小组合奖励。

```text
今日目标完成
[x] 完成 3 次工具成功   -> spark +1
[x] 摸摸咪兔 2 次       -> snack +1
[x] 晚间见面 1 次       -> memory_shard +1

全完成奖励:
"今天陪得很好喵。"
```

### 每周目标奖励模板

每周奖励应偏收藏和展示，而不是大数值。

```text
本周小约定完成
奖励:
- memory_shard +2
- 新房间边角线稿
- 周总结专属一句
```

## 里程碑奖励分配

里程碑已经定义了触发条件，本节定义每种里程碑适合发什么。

| 类别 | 优先奖励 | 示例 |
|------|---------|------|
| 时间类 milestone | `memory_shard` | 一周纪念、百天纪念 |
| 工作类 milestone | `spark` | 第 100 次工具、第 1 次写代码 |
| 互动类 milestone | `snack` / bond / 动作 | 第一次 /pet、第一条鱼 |
| 稀有 milestone | `ribbon` | SOULMATE、传说鱼、周年 |

## bond 与资源的关系

`bond` 不应该直接被资源买出来。

正确关系是:

```text
资源
  → 帮助触发互动
  → 互动产生情感反馈
  → 情感反馈和持续陪伴推动 bond
```

错误关系是:

```text
喂 100 次 = 直接涨满 bond
```

所以要保证:

- `snack` 能辅助陪伴，但不能替代陪伴
- `spark` 能推动环境成长，但不直接加很多 bond
- `memory_shard` 主要服务回顾，不直接换等级
- `ribbon` 是展示型奖励，不是数值捷径

## 消耗设计

### `snack` 消耗

| 行为 | 消耗 | 效果 |
|------|------|------|
| `feed.snack` | 1 | 普通喂食，提升心情，低概率触发专属气泡 |
| `feed.fish` | 1 条鱼 | 更高 bond 反馈，可能触发品种专属动作 |
| 回归安抚 | 1 | 缩短冷落恢复时间 |

### `spark` 消耗

| 解锁项 | 消耗 | 类型 |
|-------|------|------|
| 角落小灯 | 3 | 房间线稿 |
| 小窝 | 5 | 房间线稿 |
| 微弱星点特效 | 6 | 视觉特效 |
| 品种主题角标 | 8 | 装饰 |

### `memory_shard` 消耗

| 解锁项 | 消耗 | 类型 |
|-------|------|------|
| 一页回忆卡 | 2 | 收藏 |
| 一张纪念卡 | 3 | 展示 |
| 一页成长相册 | 4 | 收藏 |

### `ribbon` 消耗

| 解锁项 | 消耗 | 类型 |
|-------|------|------|
| 基础围巾 | 1 | 咪兔装饰 |
| 项圈吊牌 | 2 | 咪兔装饰 |
| 房间牌匾 | 2 | 场景装饰 |
| 节日主题边框 | 3 | 限定外观 |

## 防刷规则

经济系统一定要允许自然使用成长，但要避免机械刷取。

### 规则 1 — 同类行为递减

同一行为在短时间内重复触发，收益递减。

```python
def diminishing_returns(action_key: str, count_in_window: int) -> float:
    if count_in_window <= 1:
        return 1.0
    if count_in_window == 2:
        return 0.5
    return 0.0
```

适用:

- 连续同类工具调用
- 高频 `/pet`
- 刻意刷 prompt

### 规则 2 — 奖励只给第一次恢复

同一个"失败 -> 修复"链条，只奖励第一次真正恢复。

原因:

- 避免通过故意制造错误再修复来刷 `spark`

### 规则 3 — 资源上限软封顶

每日基础产出设置软上限，超过后仍有角色反馈，但资源明显减少。

建议:

| 资源 | 每日软上限 |
|------|-----------|
| `snack` | 3 |
| `spark` | 12 |
| `memory_shard` | 2 |
| `ribbon` | 1 或 0 |

超过软上限后:

- 还能拿到气泡、动作、bond
- 但资源改为低概率掉落

### 规则 4 — 目标奖励比基础刷取更优

让玩家更愿意完成"自然目标"，而不是机械重复同一操作。

例如:

- 10 次重复 `/pet` 不如完成一次"担心时安抚它"
- 20 次无意义 prompt 不如完成一次"深夜陪伴"

## 回归补偿

离开一段时间后回归，系统应给温和补偿，帮助重新进入状态。

### 补偿原则

- 补的是情绪恢复，不是数值爆炸
- 补的是重新连接的勇气，不是逼签到

### 建议方案

| 离开天数 | 补偿 |
|---------|------|
| 2-3 天 | `snack +1` |
| 4-6 天 | `snack +2`, 回归专属气泡 |
| 7-13 天 | `snack +2`, `spark +2`, 恢复期 bond x1.2 |
| 14+ 天 | `snack +3`, `spark +3`, 一张重逢回忆卡 |

## 显示格式

奖励展示不能像系统日志刷屏，而应像咪兔的反应顺手带出结果。

### 推荐格式

```text
咪兔甩了甩尾巴。
"今天也一起努力了喵。"
[获得] spark +1
```

### 稀有奖励格式

```text
咪兔忽然抬头看你，眼睛里有一颗小小的星。
[解锁] 房间角落: 小灯
```

### 回忆奖励格式

```text
[回忆新增]
标题: 第一次一起熬到这么晚
```

## 与现有系统的衔接

| 系统 | 关系 |
|------|------|
| `BondGrowth` | 奖励系统只辅助 bond，不替代 bond |
| `MilestoneTracker` | milestone 是稀有奖励和回忆奖励的重要来源 |
| `DailyRhythm` | 决定哪些时段目标更值得产出 `memory_shard` |
| `InteractionChain` | 连锁完成时额外掉落 `spark` 或稀有装饰 |
| `MiniGame` | 提供 `snack` 与鱼类素材，但不成为唯一资源入口 |
| `BreedProfile` | 决定不同品种偏好的奖励表现和专属掉落 |

## 平衡目标

理想状态下:

- 普通用户每天 5-15 分钟自然互动，就能稳定获得少量资源
- 高活跃用户不会因为刷行为而把资源曲线拉爆
- 回归用户 1-2 天内就能重新获得"我养得动它"的感觉
- 所有资源最终都指向看得见的角色变化与关系变化

## 最终体验

玩家不该觉得自己在经营一套经济系统。

玩家应该觉得:

- 今天顺手喂了它一下
- 今天一起把几件事做完了
- 今天又多留下了一点回忆
- 今天它的角落好像比昨天更像家了

这才是咪兔奖励系统真正要完成的事。
