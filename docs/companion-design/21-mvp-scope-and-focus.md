# 21 — 范围收敛与 MVP 聚焦

## 目标

这份文档不再补充新系统，而是给咪兔设定集做一次收口。

核心目的只有三个:

1. 界定什么是当前版本真正要做的
2. 明确什么内容先不做，避免复杂化
3. 把“有趣、联动、可玩性”放在“全面性”之前

## 一句话原则

咪兔首先是 **agent 的伴生系统**，不是独立的大型养成游戏。

所以当前版本的正确方向不是:

- 系统越来越全
- 面板越来越多
- 收藏越来越细
- 世界观越来越厚

而是:

- 和 agent 主流程联动更自然
- 反馈更鲜活
- 交互更顺手
- 成长更看得见

## 产品定位

咪兔在产品中的职责是:

- 给 agent 主流程增加陪伴感
- 给工作过程增加轻互动和情绪反馈
- 把“我正在用这个 agent”变成“我和这只咪兔一起在用这个 agent”

咪兔不承担的职责是:

- 替代主流程
- 变成单独的内容中心
- 提供庞大的数值养成深度
- 依靠海量玩法堆留存

## 当前版本的核心判断

如果一个功能不能明显提升以下三件事之一，就先不做:

1. 联动感
2. 可玩性
3. 陪伴感

进一步说:

- 不能增强 agent 事件反馈的，不优先
- 不能让用户 3 秒内感到“有意思”的，不优先
- 不能让用户感觉“它像活着”的，不优先

## 当前版本最重要的 4 根支柱

## 1. 事件联动

咪兔最重要的玩法，不是单独点击它，而是 **它会对 agent 主流程做出反应**。

必须优先打通:

- 用户发起提问
- 工具调用开始
- 工具调用成功
- 工具调用失败
- 连续工作
- 长时间无操作
- 深夜使用

只要这条链路成立，咪兔就不是挂件，而是伴生系统。

## 2. 轻交互

咪兔必须有少量、顺手、低成本的主动互动。

当前版本只保留最核心的 2-3 个:

- `pet`
- `feed`
- `buddy`

可选保留:

- `goal`

谨慎保留:

- `play`

原则:

- 单次交互 1-3 秒
- 不需要学习成本
- 不把用户拉离主任务

## 3. 看得见的成长

成长不能只在数据里。

当前版本只需要最小可见成长:

- bond 从 `STRANGER -> FRIEND`
- 2-3 个明显状态变化
- 1-2 个外观或角落变化
- 1 种“它更熟了”的称呼 / 态度变化

做到这一步，用户就已经能感受到“这只猫在被我养”。

## 4. 轻回忆

回忆不是为了做收藏系统，而是为了让用户觉得“它记得我”。

当前版本只保留:

- 第一次见面
- 第一次深夜陪伴
- 第一次失败后安慰
- 一周回顾
- bond 升级回顾

不需要一开始就上完整图鉴、完整相册、完整收藏体系。

## 当前 MVP 范围

## P0 必须有

这些内容缺任何一个，咪兔都还不算真正可玩。

### 1. 常驻咪兔

要求:

- 在聊天 / 工作主界面有稳定存在
- 有基础 idle 动作或状态标签
- 不打断主流程

### 2. 事件驱动情绪反馈

要求:

- 成功、失败、等待、空闲、深夜至少 5 类反应
- 先动作 / 气泡，再数字
- 用户能明显感觉“它在回应当前状态”

### 3. 两个主动互动

只保留:

- `pet`
- `feed`

要求:

- 点一下就有反馈
- 动作和文案明显不同
- 至少能推动一点关系变化

### 4. 最小成长线

只做:

- `STRANGER`
- `ACQUAINTANCE`
- `FRIEND`

先不要急着把 `CLOSE`、`SOULMATE` 做满。

### 5. 一个轻目标入口

只保留最少量的目标体验:

- 每日 2 条
- 不催打卡
- 奖励以气泡 / 小资源 / 小回忆为主

### 6. 一个回忆入口

只需要:

- 最近回忆列表
- 关键 milestone 记录
- 每周一句回顾

## P1 应该有

这些能明显增加可玩性，但不是首批必须全部完成。

### 1. 品种差异

至少让 7 品种在以下方面有区别:

- 文案口吻
- 反应偏好
- 1-2 个专属动作

### 2. 简化版时段系统

不用一次做 7 段精细时段。

先保留 3 段就够:

- 白天
- 傍晚
- 深夜

### 3. 简化版隐藏彩蛋

先做 3-5 个最容易感知的:

- 深夜摸摸
- 连续成功后的小庆祝
- 重复输入时的可爱反应

### 4. 一个可见外观兑现

例如:

- 小围巾
- 小灯
- 慢眨眼新动作

## P2 先延后

这些不是没价值，而是当前版本不该优先。

### 1. 重收藏系统

暂缓:

- 完整图鉴
- 完整相册分页
- 复杂收藏筛选
- 多层陈列系统

### 2. 重小游戏系统

暂缓:

- 多小游戏并行
- 小游戏资源循环独立膨胀
- 小游戏成为主入口

小游戏只能做“调味”，不能喧宾夺主。

### 3. 重数值系统

暂缓:

- 复杂资源树
- 多货币换算
- 连续登录深奖励
- 复杂掉落概率展示

### 4. 重内容系统

暂缓:

- 过多世界观文本
- 过多百科式设定
- 过多类型的纪念卡
- 过多的隐藏条件

## 当前版本推荐保留的功能清单

为了让范围更清楚，下面直接给出“保留 / 缩减 / 延后”。

## 保留

- 常驻咪兔精灵
- 基础情绪状态反馈
- `pet`
- `feed`
- `buddy`
- 简化版 `goal`
- 简化版 `memory`
- bond 三阶段
- 事件联动气泡
- 3-5 个隐藏彩蛋
- 1-2 个成长外观变化

## 缩减

- `play`
  只保留一个轻玩法入口，不做小游戏中心
- `goal`
  从完整系统缩到“每日 2 条 + 每周 1 条可选”
- `memory`
  从完整收藏系统缩到“最近回忆 + 周回顾 + 升级回顾”
- `collection`
  先不独立成大入口，只作为成长结果附着在 `buddy` / `memory`
- `album`
  先不独立深做，只保留 1-2 张阶段快照

## 延后

- 完整图鉴
- 完整房间系统
- 完整收藏分类
- 完整小游戏宿主
- 大量阶段成长
- 大量稀有演出
- 完整 SOULMATE 长线内容

## “有趣”应该从哪里来

当前版本的有趣，不应该主要来自“内容多”，而应该来自“反应妙”。

最值得优先打磨的有趣来源:

### 1. 对当前状态反应得准

例如:

- 失败时它担心
- 成功时它松一口气
- 深夜时它困但愿意陪着

### 2. 动作和文字搭得上

例如:

- 先耳朵一动，再说一句话
- 先慢眨眼，再显示关系加深

### 3. 有一点意外之喜

例如:

- 连续成功后突然庆祝
- 深夜出现专属台词
- 重复某个动作时触发隐藏反应

### 4. 变化虽小但能看见

例如:

- 它开始更靠近你
- 它的角落多了盏小灯
- 它第一次叫你新的称呼

## 设计约束

为了防止又走向全面化，新增功能必须满足以下约束。

## 约束 1

一个新功能如果需要单独教育用户怎么用，就太重了。

## 约束 2

一个新功能如果不能在 3 秒内给出感知反馈，就不适合作为伴生系统核心。

## 约束 3

一个新功能如果让用户离开 agent 主任务超过 30 秒，就必须重新评估。

## 约束 4

一个新功能如果主要价值只是“系统更完整”，而不是“体验更有趣”，就先不做。

## 成功标准

当前版本是否成功，不看系统数量，看下面这些问题是否成立。

### 用户会不会这样想

- “它真的在陪我工作。”
- “我失败的时候它有反应。”
- “我会顺手摸它一下。”
- “我想看看它今天怎么样。”
- “这只猫开始有点像我的那只了。”

### 团队应该看到的指标方向

- 用户会主动触发 `pet` / `feed`
- 用户愿意偶尔打开 `buddy`
- 用户能感知到事件反馈差异
- 用户对“深夜反应”“失败安慰”“连续成功庆祝”有记忆点

## 推荐实施顺序

### Step 1

先做“联动成立”:

- 事件 -> 情绪
- 情绪 -> 动作 / 气泡

### Step 2

再做“主动可玩”:

- `pet`
- `feed`
- `buddy`

### Step 3

再做“关系沉淀”:

- bond 三阶段
- 关键回忆
- 周回顾

### Step 4

最后才做“锦上添花”:

- 品种差异深化
- 外观细节
- 少量彩蛋

## 最终结论

咪兔当前阶段最重要的，不是“做全”。

而是做到这四件事:

1. 会陪
2. 会回应
3. 会长大
4. 有一点点让人想继续看的乐趣

只要这四件事成立，它就是一个成立的 agent 伴生系统。

其他更完整、更庞大的系统，都应该在这个最小闭环跑通之后再考虑。
