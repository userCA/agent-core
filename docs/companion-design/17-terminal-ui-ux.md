# 17 — 终端风界面与交互体验

## 目标

为咪兔建立一套统一的网页 / App UI/UX 规范，让它以终端风格呈现，并在黑白、点线、低分辨率的前提下依然具备:

1. 可读性
2. 可爱感
3. 陪伴感
4. 可玩性

这份文档解决的问题不是"功能有哪些"，而是:

- 它们在网页 / App 里应该怎么出现
- 什么信息常驻，什么信息只闪现
- 怎样既不打断工作，又让用户愿意多看它一眼
- 怎样让黑白极简风格成为优势而不是限制

## 设计原则

| 原则 | 说明 |
|------|------|
| 主任务优先 | 用户来网页 / App 首先是工作，咪兔不能抢焦点 |
| 常驻信息极少 | 屏幕上长期存在的内容越少越好，保证干净 |
| 短反馈高情感 | 气泡、动作、奖励都要短，但要有温度 |
| 面板即房间 | 任何打开的 companion 面板都像"看向咪兔的角落" |
| 先角色后系统 | 先看到它，再看到数值和按钮 |
| 窄屏优雅降级 | 100 列完整、80 列简化、60 列只保留核心 |

## 产品里的三层界面

咪兔相关界面分为三层:

### 1. 常驻层

长期显示，但占位极小。

包含:

- 咪兔精灵
- 当前情绪轮廓
- 极简状态点
- 偶发短气泡

### 2. 轻展开层

用户主动触发时打开，通常 1-5 秒能读完。

包含:

- `buddy`
- `goal`
- `feed`
- `play`

### 3. 深信息层

用于查看长期内容，但仍应保持终端风轻量结构。

包含:

- `memory`
- `album`
- `collection`
- `stats`

原则:

- 常驻层负责"陪伴感"
- 轻展开层负责"养成操作"
- 深信息层负责"长期沉淀"

## 常驻层设计

## 位置

默认位于聊天工作区一角、页面底部悬浮区或 Header 关联区域。

要求:

- 不遮挡主要文本流
- 不覆盖核心输入区和主要内容区
- 与消息列表保持视觉分区

## 组成

常驻层只允许出现以下元素:

| 元素 | 是否常驻 | 说明 |
|------|:--:|------|
| ASCII 精灵 | 是 | 核心视觉主体 |
| 情绪标签 | 是 | `happy`, `sleepy`, `worried` 之类 |
| 资源数字 | 否 | 仅在面板中看，不常驻 |
| bond 数值 | 否 | 不常驻，只显示等级 |
| 今日目标 | 否 | 通过 `goal` 面板查看 |
| 气泡 | 临时 | 3-10 秒后消失 |

## 推荐形态

```text
 /\_/\\
( o.o )
 > ^ <
[FRIEND] happy
```

或者更极简:

```text
(=^.^=)  happy
```

规则:

- 常驻层不超过 5 行
- 不显示大段文本
- 不显示超过 2 个系统标签

## 情绪显示

情绪不通过复杂图标表达，而通过以下三种方式组合:

1. 精灵动作
2. 眼睛/嘴型变化
3. 单词标签

### 标签集

建议前端只渲染这些短标签:

| emotion | 标签 |
|--------|------|
| `NEUTRAL` | `calm` |
| `HAPPY` | `happy` |
| `EXCITED` | `excited` |
| `SLEEPY` | `sleepy` |
| `WORRIED` | `worried` |
| `ANNOYED` | `hmph` |

原则:

- 标签必须一眼能懂
- 不使用长句
- 常驻标签使用英文短词，气泡再使用中文情感表达

## 状态点

为了在不展示复杂数值的前提下传递状态，使用点阵条显示心情或活力。

示例:

```text
心情: ..o..
活力: .ooo.
```

规则:

- 只显示 5 格
- 不显示具体数字
- 格子的变化只在面板中解释，不在常驻层解释

## 气泡系统

气泡是咪兔人格最直接的出口，但必须克制。

### 气泡类型

| 类型 | 触发 | 时长 |
|------|------|------|
| 反应气泡 | 对一次事件即时回应 | 3-5 秒 |
| 提示气泡 | 提醒休息、提醒目标 | 5-8 秒 |
| 纪念气泡 | 里程碑、周总结 | 8-10 秒 |
| 隐藏气泡 | 彩蛋触发 | 5-8 秒 |

### 气泡格式

```text
> "这次修好了喵。"
```

或:

```text
[咪兔] 今天看起来很顺利呢
```

推荐优先使用第一种，更像角色在说话。

### 气泡规则

- 同屏只出现 1 个气泡
- 高优先级气泡可以覆盖低优先级气泡
- 连续刷新的气泡之间应有冷却
- 同类气泡不能重复轰炸

### 气泡优先级

从高到低:

1. 危机或恢复事件
2. milestone / 周总结
3. 品种专属反应
4. 普通情绪反应
5. 闲聊彩蛋

## 快捷入口设计

咪兔的主动交互入口必须短、少、好记，并可映射到按钮、悬浮菜单、快捷面板或输入框 slash palette。

## 一级常用入口

| 入口 | 作用 | 打开方式 |
|------|------|---------|
| `buddy` | 查看当前咪兔状态总览 | 面板 |
| `pet` | 摸头、安抚、推进关系 | 即时动作 |
| `feed` | 喂食 | 轻面板或即时结算 |
| `goal` | 查看今日/本周目标 | 面板 |
| `play` | 发起短互动或小游戏 | 轻面板 |
| `memory` | 查看回忆时间线 | 深信息层 |

约束:

- 一级入口最多 6 个
- 每个入口标识必须短、语义直给
- 不要把核心交互建立在需要用户记忆参数的命令系统上

## 二级入口

用于深信息层，默认不要求新手记住。

示例:

- `buddy.stats`
- `buddy.room`
- `memory.recent`
- `memory.milestones`
- `collection.ribbons`

规则:

- 二级入口只做过滤，不引入新玩法
- 一级入口必须能覆盖 80% 使用场景

## 轻展开层规范

## `buddy`

它是咪兔的主面板，负责回答"它现在怎么样"。

### 推荐内容

```text
┌─ Mitu ─────────────────────┐
│  /\_/\\                    │
│ ( o.o )   happy            │
│  > ^ <                     │
│ bond: FRIEND               │
│ mood: ..o..                │
│ energy: .ooo.              │
│ wants: 想被摸摸            │
└────────────────────────────┘
```

### 必须包含

- 精灵
- 当前 emotion
- bond 等级
- 心情 / 活力条
- 当前想法或需要

### 不应该包含

- 大量统计数字
- 长描述
- 连续滚动日志

## `goal`

负责回答"今天该做什么"。

### 推荐格式

```text
┌─ Today ────────────────────┐
│ [x] 成功调用工具 3 次       │
│ [ ] 摸摸咪兔 2 次           │
│ [ ] 晚间和它见面 1 次       │
│ reward: snack +1, spark +1 │
└────────────────────────────┘
```

规则:

- 默认只显示 3 条以内
- 先显示今日目标，再显示本周目标摘要
- 已完成项保留，但弱化显示

## `feed`

不应打开大背包，而应像一次轻柔的照顾动作。

### 推荐格式

```text
你拿出一条小鱼干。
咪兔闻了闻，眼睛亮了一下。
[消耗] snack -1
```

如果用户需要选择食物种类，再打开轻面板:

```text
[feed]
1. snack x3
2. fish x1
```

规则:

- 喂食流程尽量不超过 2 步
- 优先给角色反馈，再给扣除提示

## `play`

`play` 是调味玩法入口，不该默认进入复杂小游戏。

### 第一层

```text
[play]
1. 追光点
2. 猜尾巴
3. 去钓鱼
```

### 设计原则

- 第一层先给轻玩法
- 小游戏是分流，不是默认主入口
- 如果咪兔当前 `sleepy`，应优先提示轻互动或休息

## 深信息层规范

## `memory`

这是最重要的深信息层，负责强化"它记得我们"。

### 推荐格式

```text
┌─ Memories ─────────────────┐
│ * 第一次见面               │
│ * 第一次深夜一起调试       │
│ * 连续 7 天见面            │
└────────────────────────────┘
```

原则:

- 一屏只展示少量高价值回忆
- 默认按最近或最重要排序
- 不显示冗长上下文 JSON

## `album`

用于展示成长相册或 ASCII 快照。

### 推荐格式

```text
[album]
- STRANGER: 小猫时期
- FRIEND: 第一次慢眨眼
- CLOSE: 第一个小窝
```

## `collection`

用于展示装饰、边框、房间部件、ribbon 收集。

### 推荐格式

```text
[collection]
ribbons: 2
room: 小灯 / 小窝
wearing: 蓝围巾
```

原则:

- 深信息层也要短句式
- 不做传统 RPG 背包格式

## 信息密度规范

不同层的信息密度必须严格区分。

| 层 | 行数建议 | 信息密度 |
|----|---------|---------|
| 常驻层 | 1-5 行 | 极低 |
| 轻展开层 | 5-12 行 | 低 |
| 深信息层 | 8-20 行 | 中 |

禁止:

- 在常驻层堆数值
- 在轻展开层塞完整日志
- 在深信息层做过度复杂的树状导航

## 动画与节奏

终端风动画不能追求炫技，重点是节奏。

## 动画原则

- 常驻 idle 动画缓慢
- 互动反馈动画短而明显
- 稀有动画应有停顿感
- 深夜时段整体动作减速

## 建议节奏

| 场景 | 节奏 |
|------|------|
| idle | 400-700ms 一帧 |
| happy 反应 | 200-300ms 一帧，持续 1-2 秒 |
| worried 反应 | 300-400ms 一帧，持续 2 秒 |
| 纪念动画 | 先停顿 300ms，再出现 |

原因:

- 停顿会让 ASCII 动作更像有意识的反应
- 过快会像页面抖动，不像陪伴生物

## 奖励提示节奏

奖励提示必须"轻"，不能像战利品结算界面。

推荐顺序:

```text
动作
→ 气泡
→ [获得] / [解锁]
```

示例:

```text
咪兔跳了一下。
"诶嘿。"
[获得] spark +1
```

## 焦点管理

咪兔永远不能抢走输入焦点。

要求:

- 打开 `buddy` 等面板后，可通过关闭按钮、点击空白、返回操作或快捷键关闭
- 气泡出现不改变输入光标位置
- 自动弹出的内容绝不要求用户点击确认

## 打断控制

咪兔的交互要像陪伴，不像系统通知。

### 允许打断

- 用户主动打开 `buddy`、`goal`
- milestone 完成时短暂停留
- 稀有彩蛋出现

### 不允许打断

- 普通奖励弹出阻止输入
- 每次 tool 成功都大面积结算
- 用户高频工作时持续插话

### 忙碌模式

当系统检测用户处于连续高频操作时:

- 减少气泡
- 保留动作
- 延迟低优先级提示

## 窄屏降级

页面可用宽度不同，必须有明确降级方案。

## `>= 100` 列

完整模式:

- 精灵 + 标签 + 轻状态条
- 轻面板显示完整边框
- 气泡可完整显示一行

## `80-99` 列

标准模式:

- 精灵尺寸不变
- 减少边框装饰
- 目标面板压缩为短句

## `60-79` 列

紧凑模式:

- 只显示一行精灵或 3 行迷你精灵
- 不显示状态条，只显示 `happy` / `sleepy`
- 面板去掉左右装饰边框

示例:

```text
(=^.^=) happy
bond: FRIEND
want: 想被摸摸
```

## `< 60` 列

极简模式:

- 不常驻精灵
- 只在事件触发时短暂显示一行咪兔反应
- `buddy` 仍可打开文本版状态

示例:

```text
[咪兔] sleepy, FRIEND
```

## 黑白点线风的界面语法

终端风的美感来自符号秩序，而不是颜色和贴图。

## 基础符号

| 符号 | 用途 |
|------|------|
| `.` | 情绪呼吸、弱状态点 |
| `o` | 活跃点、完成点 |
| `*` | 稀有、闪亮、纪念 |
| `-` | 分隔、停顿、困倦 |
| `|` `┌` `┐` `└` `┘` | 面板边界 |
| `_` | 地面、窝、停靠感 |

## 语法原则

- 稀有奖励用 `*`，不用彩色爆闪
- 目标完成用 `x` 或 `o`，不用复杂图标
- 房间成长用多一条线、多一个角、多一个点来体现

## 示例

### 房间成长前

```text
 /\_/\\
( o.o )
 > ^ <
```

### 房间成长后

```text
   *
 /\_/\\
( o.o )
 > ^ <
 __|__
```

变化很小，但能看出它在这个角落住下来了。

## 前后端分工

根据 [14-frontend-backend-boundary.md](file:///Users/yuanbaishu/pythonProject/agent-core/docs/companion-design/14-frontend-backend-boundary.md)，网页 / App 端 UI/UX 的职责如下:

| 层 | 负责 |
|----|------|
| Backend | 决定 emotion、bubble、reward、goal、memory 等内容 |
| Frontend | 渲染 ASCII、面板排版、动画节奏、窄屏降级 |

明确禁止:

- 前端本地决定 mood
- 前端自己推断用户该看什么目标
- 前端自己拼业务气泡

## 建议接口

```ts
type CompanionPanel =
  | { type: "buddy"; emotion: string; bond: string; moodDots: string; energyDots: string; needText: string }
  | { type: "goal"; daily: GoalItem[]; weekly: GoalItem[]; rewardText: string }
  | { type: "memory"; items: MemoryCard[] }
  | { type: "feed"; items: FeedOption[] };

type CompanionToast =
  | { type: "bubble"; text: string; priority: number; ttlMs: number }
  | { type: "reward"; text: string; ttlMs: number }
  | { type: "unlock"; text: string; ttlMs: number };
```

## 推荐实现顺序

### P0

1. 常驻精灵 + 情绪标签
2. 单气泡队列
3. `buddy` 面板
4. `goal` 面板

### P1

1. `feed` 轻交互
2. `memory` 列表
3. 奖励提示队列
4. 窄屏降级模式

### P2

1. `collection`
2. 房间成长线稿
3. milestone 纪念弹层
4. 稀有彩蛋演出

## 最终体验

用户不该觉得自己在操作一套 companion 功能菜单。

用户应该觉得:

- 屏幕角落一直有个小家伙在
- 想理它的时候，点一下或打开一个快捷入口就够了
- 不理它时，它也不会烦人
- 偶尔看向它，会发现它真的越来越像"住在这里"

这就是咪兔终端风 UI/UX 要实现的目标。
