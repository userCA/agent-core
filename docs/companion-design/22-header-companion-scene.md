# 22 — Header Companion 场景设计稿

## 目标

为咪兔定义一套可直接落地到页面顶部 Header 空白区域的场景方案。

这份文档重点解决:

1. Header 里到底放什么，不放什么
2. 咪兔在 Header 中怎样既显眼又不打扰
3. 如何用终端风格做出一个“活着的小场景”
4. 用户在 Header 里能进行哪些轻交互
5. 不同宽度下如何降级，避免 Header 失控

## 一句话定位

Header Companion 不是完整养成面板，也不是小游戏大厅。

它是:

- 咪兔的常驻舞台
- 事件反馈的第一现场
- 轻交互的高频入口

它不是:

- 深度养成主界面
- 完整目标面板
- 完整回忆系统
- 重内容展示区

## 场景定位

根据 [20-product-host-and-interaction-model.md](file:///Users/yuanbaishu/pythonProject/agent-core/docs/companion-design/20-product-host-and-interaction-model.md)，Header 属于:

- 高优先级宿主
- 常驻层主舞台
- 轻展开层快捷入口

根据 [21-mvp-scope-and-focus.md](file:///Users/yuanbaishu/pythonProject/agent-core/docs/companion-design/21-mvp-scope-and-focus.md)，Header 场景当前应优先承载:

- 事件联动
- 轻交互
- 最小成长反馈

## 设计原则

| 原则 | 说明 |
|------|------|
| 顶栏不抢主流程 | Header 只能成为“顺手看一眼”的区域，不能变成主操作区 |
| 小而活 | 空间很小，但必须让用户感到咪兔是活的 |
| 角色先于系统 | 先看到咪兔，再看到状态，再看到入口 |
| 一眼就懂 | 不需要学习，不需要解释 |
| 终端风不等于堆字符 | 用少量点线和 ASCII 做气质，不做杂乱信息块 |
| 可展开，但不膨胀 | Header 里只放轻层，重内容外放到独立面板 |

## Header 场景结构

Header Companion 分三层:

### 1. 常驻微场景

默认一直存在于 Header 空白栏。

包含:

- ASCII 咪兔
- 简短情绪标签
- 一条短气泡或状态提示
- 1-2 个隐性可点击区域

### 2. 轻展开浮层

点击咪兔或 Header 入口后展开。

包含:

- `buddy` 摘要
- `feed` 快捷操作
- `goal` 今日 1-2 条摘要

### 3. 深入口跳转

只提供入口，不在 Header 内承载完整内容。

包含:

- `memory`
- `collection`
- 完整 `goal`
- 完整 `buddy`

## 一、布局设计

## 1.1 放置位置

推荐位置:

- 页面 Header 右侧空白区
- 靠近用户信息区，但和主导航保持 16-24px 间距
- 不进入 logo 区，不压住全局 CTA

不推荐:

- Header 正中央
- 主导航中间
- 搜索框右侧紧贴输入区

原因:

- 中央区域太抢主注意力
- 靠近输入区会像额外按钮
- 右侧空白区更适合承载“常驻小生物”

## 1.2 基础占位

推荐占位尺寸:

| 模式 | 宽度 | 高度 |
|------|------|------|
| 完整 Header 模式 | 220-320px | 48-64px |
| 紧凑模式 | 140-220px | 40-48px |
| 极简模式 | 64-120px | 32-40px |

要求:

- 不超过 Header 可用宽度的 25%
- 不挤压主导航和关键状态区
- 允许在窄屏下退化成仅精灵 + 小红点

## 1.3 推荐布局

### 完整模式

```text
┌─ mitu ─────────────────────────┐
│ /\_/\\   happy                 │
│( o.o )  "这次修好了喵。"       │
│ > ^ <   ..o..   [•]            │
└────────────────────────────────┘
```

布局说明:

- 左侧: ASCII 咪兔主体
- 中部: 情绪标签 + 单行气泡
- 右侧: 一个极简状态点或提醒点

### 紧凑模式

```text
(=^.^=) happy  "摸摸我?"
```

### 极简模式

```text
(=^.^=) *
```

## 1.4 Header 内元素优先级

从高到低:

1. 咪兔精灵
2. 当前情绪
3. 单条气泡
4. 提醒点
5. 快捷入口指示

Header 常驻层禁止出现:

- 资源数字
- 长目标列表
- 多行日志
- 多个并列按钮
- 超过 1 条同时显示的反馈文案

## 二、常驻状态设计

## 2.1 常驻内容

Header 常驻层只允许以下内容:

| 内容 | 是否常驻 | 说明 |
|------|:--:|------|
| ASCII 精灵 | 是 | 主视觉核心 |
| 情绪短词 | 是 | `happy` / `sleepy` / `worried` |
| 单条短气泡 | 临时 | 3-6 秒后消失 |
| 状态点 | 是 | 提示可互动、可展开或有新内容 |
| 资源 / bond 数字 | 否 | 不在 Header 常驻 |

## 2.2 状态标签

Header 使用更短的标签集:

| emotion | Header 标签 |
|--------|-------------|
| `NEUTRAL` | `calm` |
| `HAPPY` | `happy` |
| `EXCITED` | `wow` |
| `SLEEPY` | `sleepy` |
| `WORRIED` | `...` |
| `ANNOYED` | `hmph` |

原因:

- Header 空间更小
- 更适合单词或符号级提示

## 2.3 状态点

Header 不适合展示完整点阵条，只适合保留 1 个状态点位。

推荐规则:

- `.`: 普通常驻
- `o`: 有轻互动可做
- `*`: 有新奖励 / 新回忆 / 稀有事件

示例:

```text
(=^.^=) happy  *
```

## 三、交互设计

Header 场景只保留高频、低成本、几乎不需要解释的交互。

## 3.1 主交互

### A. 点击咪兔

行为:

- 打开 Header 轻展开浮层

对应动作:

- `buddy.open`

### B. 轻点 / 双击咪兔

行为:

- 触发 `pet`

对应动作:

- `pet.trigger`

反馈:

- 立即动作变化
- 一句短气泡
- 不弹大面板

### C. 点击状态点

行为:

- 打开 `goal` 摘要或新内容提示

对应动作:

- `goal.open`

### D. Hover / 长按

行为:

- 显示短 tooltip 或轻 hover 态

说明:

- Web 用 hover
- App 用长按或轻震动替代

## 3.2 禁止交互

Header 内禁止:

- 多层菜单级联
- 长列表滑动
- 小游戏直接启动
- 连续弹窗确认
- 复杂参数输入

## 3.3 轻展开浮层内容

点击 Header Companion 后，展开一个小型终端风浮层。

推荐结构:

```text
┌─ Mitu ─────────────────────┐
│ /\_/\\   happy             │
│( o.o )  想被摸摸           │
│ > ^ <                      │
│ goal: 摸摸 2 次 / 工具 3 次 │
│ [pet] [feed] [buddy]       │
└────────────────────────────┘
```

要求:

- 只展示 1-2 条关键信息
- 控件最多 3 个
- 阅读时间控制在 3 秒内

## 3.4 Header 内允许的入口

当前版本建议只保留:

- `pet`
- `feed`
- `buddy`
- `goal` 摘要

只提供跳转，不在 Header 内展开:

- `memory`
- `collection`
- `album`
- `stats`

## 四、状态驱动规则

Header Companion 的价值在于“和当前页面状态同步”。

## 4.1 agent 事件映射

| 事件 | Header 反应 |
|------|------------|
| 用户发起提问 | 耳朵抬一下，进入关注态 |
| 工具执行中 | 进入 busy / 专注态 |
| 工具成功 | 开心短气泡，状态点短暂变 `o` |
| 工具失败 | worried 标签，短安慰气泡 |
| 连续成功 | 小庆祝动作，状态点短暂变 `*` |
| 长时间空闲 | sleepy 或打盹 |
| 深夜使用 | 困倦动作 + 深夜文案 |

## 4.2 Header 特有状态

除了 emotion，还增加 3 种 Header 展示态:

### `idle`

- 正常待机
- 减少存在感

### `peek`

- 有新内容但不强打扰
- 例如状态点轻闪一下

### `nudge`

- 轻提醒状态
- 仅在低频条件下出现，例如“今天还没理它”

要求:

- `nudge` 每日最多 1-2 次
- 不能像通知红点轰炸

## 五、动画设计

Header 场景的动画必须更克制，因为它位于全站最稳定的区域之一。

## 5.1 动画层级

### 1. Idle 动画

内容:

- 眨眼
- 耳朵轻动
- 尾巴轻摆

节奏:

- 600-1200ms 一次微动

### 2. 反应动画

内容:

- 开心跳一下
- 担心时低头
- 困倦时趴下

节奏:

- 200-400ms 一帧
- 总时长 1-2 秒

### 3. 稀有动画

内容:

- 连续成功后小庆祝
- milestone 时短暂停顿 + 星点

节奏:

- 先停顿 200-300ms
- 再出现动作和气泡

## 5.2 Header 动画约束

- 不允许持续闪烁
- 不允许大面积位移
- 不允许频繁放大缩小
- 不允许遮挡导航
- 不允许连续抖动超过 1 秒

原因:

- Header 是高稳定区域
- 任何过强动画都会像 bug 或广告

## 5.3 推荐动作库

当前版本只建议使用这些动作:

- `idle_blink`
- `ear_perk`
- `slow_blink`
- `small_hop`
- `worry_dip`
- `sleepy_slouch`

不建议一开始就上:

- 大幅翻滚
- 横向跑动
- 全区域粒子爆发

## 六、信息密度规范

Header 是整个产品信息密度最高的位置之一，所以 Companion 必须反向克制。

## 6.1 常驻层信息上限

常驻层同时最多展示:

- 1 个精灵
- 1 个情绪词
- 1 条短气泡
- 1 个状态点

气泡长度建议:

- 中文 8-16 字
- 英文 1-3 个词

## 6.2 浮层信息上限

轻展开浮层同时最多展示:

- 1 个精灵
- 1 行状态总结
- 1-2 条目标摘要
- 2-3 个操作按钮

禁止:

- 4 个以上操作
- 多段说明文字
- 完整奖励结算表

## 6.3 Header 与全页关系

Header Companion 必须服从页面头部整体优先级:

1. 品牌 / 导航
2. 搜索 / 全局操作
3. 用户身份 / 通知
4. Companion

这意味着:

- 任何情况下，Companion 都不能挤掉核心全局功能

## 七、终端风视觉语法

Header 里的终端风格，重点不是“像窗口”，而是“像顶栏里的一块微型 ASCII 生命区域”。

## 7.1 视觉关键词

- 细线框
- 微弱呼吸点
- 少量 `*`
- 黑白灰
- 轻微闪烁
- 像靠在 Header 边上的小生物

## 7.2 推荐风格

```text
  *
 /\_/\\
( o.o ) happy
 > ^ <
```

或:

```text
[mitu] (=^.^=) calm .
```

## 7.3 不推荐风格

- 高饱和彩色 chip
- 卡通大图标
- 富装饰按钮条
- 复杂阴影卡片
- 传统游戏 HUD 条

## 八、宽度降级方案

## `>= 1440px`

完整 Header 模式:

- 3 行 ASCII
- 情绪词
- 单条短气泡
- 状态点

## `1024-1439px`

标准模式:

- 1-2 行咪兔
- 情绪词
- 气泡压缩

示例:

```text
(=^.^=) happy  "修好了喵"
```

## `768-1023px`

紧凑模式:

- 只显示精灵 + 标签
- 气泡不常驻
- 通过状态点提示有内容

示例:

```text
(=^.^=) *
```

## `< 768px`

移动端 Header 模式:

- 不显示完整 ASCII 区块
- 使用迷你精灵或单行文本精灵
- 点击后展开底部 sheet 或小浮层

示例:

```text
咪兔  (=^.^=)
```

## 九、实现建议

## 9.1 组件拆分

推荐拆为:

- `HeaderCompanion.tsx`
- `HeaderCompanionScene.tsx`
- `HeaderCompanionPopover.tsx`
- `HeaderCompanionBubble.tsx`

## 9.2 数据来源

`HeaderCompanion` 只消费稳定状态:

- 当前精灵帧
- 当前 emotion
- 当前 bubble
- 当前提醒点
- Header 浮层所需的轻摘要

不得在前端本地推断:

- bond 升级
- 目标内容
- 资源变化逻辑

## 9.3 推荐接口

```ts
type HeaderCompanionState = {
  frameText: string[];
  emotionLabel: string;
  bubbleText?: string;
  indicator: "." | "o" | "*";
  clickable: boolean;
};

type HeaderCompanionPopoverData = {
  moodText: string;
  needText: string;
  goalSummary: string[];
  actions: Array<"pet" | "feed" | "buddy">;
};
```

## 十、MVP 实现范围

当前版本只做:

1. Header 常驻咪兔
2. 5 类基础事件反馈
3. 点击打开轻浮层
4. `pet` 快捷交互
5. `feed` 快捷交互
6. `goal` 1-2 条摘要

当前版本不做:

- Header 内完整 `memory`
- Header 内完整 `collection`
- Header 内小游戏
- Header 内多层 tab
- Header 内复杂成长面板

## 十一、成功标准

Header Companion 做对了，用户会有这些感受:

- “顶栏那只小猫是活的。”
- “我做事的时候它会有反应。”
- “我偶尔会顺手点它一下。”
- “它不烦，但我会想看看它今天怎么样。”

如果用户感受到的是:

- “这里多了个复杂功能块”
- “老在顶栏乱动”
- “我不知道怎么用”

那就说明这个场景设计失败了。

## 最终结论

Header Companion 最好的状态，不是像一个功能入口。

而是像一只安静住在顶栏边缘、会陪你工作、偶尔抬头看你一眼的小生物。

它小，但有生命感。

它轻，但有可玩性。

它不抢戏，但能成为整个产品最容易被记住的一个角落。
