# 23 — Header SVG 收敛方案

## 目标

为 Header Companion 制定一套 SVG 收敛方案，解决当前“精细像素面板不像猫、太满、太像展示板”的问题。

这份方案不追求把猫画得更复杂，而是回答:

1. Header 里的 SVG 应该负责什么
2. Header 里的 SVG 不应该负责什么
3. 怎么保留终端风，又不丢掉“像猫”的第一识别
4. 如何让 SVG 方案比当前精细版更适合顶栏

## 核心判断

当前问题不是 “SVG 不适合”。

当前问题是:

- 猫本体信息太多
- 颜色层次太多
- 面板元素太多
- 整体更像像素插画卡片，而不是 Header 常驻 companion

所以收敛方向不是放弃 SVG，而是:

```text
把 SVG 从“精细插画载体”
收回成“轻结构与终端风语法载体”
```

## 一句话方案

猫继续保持强轮廓、强表情、少细节。

SVG 主要负责:

- 线框
- 状态点
- 气泡容器
- 微型环境元素
- Hover / 点击反馈

而不是负责“把猫画得更真”。

## 设计原则

| 原则 | 说明 |
|------|------|
| 猫先被认出来 | 第一眼必须先认出“是猫” |
| 轮廓优先于上色 | 耳朵、脸型、眼睛比毛色层次更重要 |
| SVG 做结构，不做堆料 | 让 SVG 承担边界和节奏，不承担插画复杂度 |
| Header 不要展示板感 | 不能像像素作品展板或宠物资料卡 |
| 黑白灰优先，点缀色克制 | 只保留极少量强调色 |
| 元素默认隐藏 | 灯、窝、星点、状态条都不应该全时常驻 |

## 问题诊断

基于现有 [svg-pixel-panel-preview.html](file:///Users/yuanbaishu/pythonProject/agent-core/docs/companion-design/appendix/svg-pixel-panel-preview.html)，主要问题有四类。

## 1. 猫脸过度绘制

当前问题:

- 眼周、鼻子、嘴、下巴、毛色层次过多
- 头部像素块太细
- 小尺寸下第一识别不稳定

表现结果:

- 看起来像一张小插画
- 不像 Header 里的一只小生物

## 2. 环境元素过多

当前问题:

- 地面线
- 小窝
- 小灯
- 粒子
- 状态点
- 气泡

同时常驻。

表现结果:

- Header 负担过重
- 视线被环境分走，猫反而不是主角

## 3. 颜色层级过多

当前问题:

- 主色、浅色、高光、阴影、鼻口颜色层数过多

表现结果:

- 小面积里发灰发杂
- 失去终端风的干净感

## 4. 面板感太强

当前问题:

- 整体更像一块像素 UI 卡片
- 不像 Header 边缘自然长出来的小区域

表现结果:

- 像功能模块
- 不像 companion

## 收敛目标

Header SVG 收敛后，应该满足:

1. 远看一眼就是猫
2. 近看有终端风味道
3. 默认状态很轻
4. 事件发生时才稍微亮一下
5. 不把 Header 变成一块复杂面板

## 角色与结构分工

## 1. 猫本体负责

- 耳朵轮廓
- 头脸轮廓
- 眼睛和嘴型
- 情绪变化
- 轻动作

## 2. SVG 外壳负责

- Header 场景边界
- 细线框 / 微弱底线
- 状态点
- 气泡边框
- 点击热区
- 少量星点 / 小灯等低频元素

## 3. 不再由 SVG 负责

- 厚重毛色体积表现
- 面部明暗建模
- 完整房间展示
- 多个环境部件同时常驻

## 猫本体收敛规则

## 1. 脸部识别核心

猫脸在 Header 里只保留这些核心信息:

- 左右耳
- 两只眼
- 小嘴
- 一个稳定脸型

不再强求:

- 鼻头高光
- 面颊渐变
- 下巴多层白毛
- 细碎胡须纹理

## 2. 像素尺寸建议

推荐把 Header 猫本体压缩到:

- 宽 12-16 格
- 高 8-12 格

目的:

- 保证缩小时仍然像猫
- 不需要过多细节也能成立

## 3. 色彩建议

猫本体最多使用:

- 1 个主色
- 1 个轮廓色
- 1 个高光色

例如橘猫:

- 主色: 橘
- 轮廓: 深棕
- 高光: 浅米

不要再使用 5-7 层色块。

## 4. 品种差异做法

品种差异不要主要靠复杂花色，而应该靠:

- 脸型
- 耳型
- 眼型
- 一处特征记号

例如:

- 暹罗: 更细长眼型
- 黑猫: 高对比眼睛
- 奶牛: 一个黑白块识别点
- 布偶: 更圆、更蓬
- 折耳: 耳朵下折

## Header 常驻层收敛规则

默认常驻只保留四类元素:

1. 猫
2. 情绪词
3. 一个状态点
4. 一条短气泡

默认不常驻:

- 小窝
- 小灯
- 地面线
- 多颗粒子
- 状态条
- 多行气泡框

## 元素显隐规则

## 1. 默认态

显示:

- 猫
- 情绪词
- 状态点

可选:

- 极短气泡

## 2. 事件态

显示:

- 猫动作变化
- 短气泡
- 状态点从 `.` 变成 `o` 或 `*`

## 3. 稀有态

才允许出现:

- 单个星点
- 小灯微亮
- 轻边框强调

## 4. 深夜态

才允许出现:

- 一点点暗调
- `z`
- 微弱灯光

## Header SVG 的三种模式

## 模式 A — 极简常驻

用途:

- 日常最常见状态

组成:

- 猫
- 情绪词
- 状态点

示例:

```text
(=^.^=) calm .
```

对应 SVG 特征:

- 无边框
- 无气泡框
- 无环境物件

## 模式 B — 反馈常驻

用途:

- 成功 / 失败 / 深夜等事件反馈

组成:

- 猫
- 一条短气泡
- 状态点

示例:

```text
(=^.^=) happy  "修好了喵"
```

对应 SVG 特征:

- 气泡容器出现
- 线框极细
- 不出现房间元素

## 模式 C — 轻展开浮层

用途:

- 用户点击 Header 后的 1 层展开

组成:

- 猫
- 一行状态
- 1-2 条摘要
- 2-3 个按钮

对应 SVG 特征:

- 可以出现边框
- 允许一条地面线
- 仍不出现完整房间和大量装饰

## 推荐视觉语法

## 1. 线条

- 使用 1px 或极细线
- 线框只作为边界，不做装饰纹样

## 2. 状态点

- `.`: 常驻
- `o`: 可互动
- `*`: 稀有或新内容

## 3. 边框

边框只在以下场景出现:

- 气泡
- 浮层
- 轻 hover

常驻态尽量不画完整包围框。

## 4. 高亮

高亮只允许出现在:

- 眼睛
- 状态点
- 单个星点
- 小灯

不能整块发光。

## 不推荐做法

以下方向建议直接放弃:

- 继续增加猫的面部像素层次
- 给每个品种都做高度精细的彩色像素立绘
- Header 常驻完整小窝和房间
- 默认常驻粒子和装饰
- 让 SVG 面板像游戏 HUD

## 推荐做法

建议采用以下组合:

## 方案 1 — ASCII 主体 + SVG 外壳

最稳妥。

做法:

- 猫仍然是 ASCII / 预格式文本风格
- SVG 只负责气泡、边框、状态点和微装饰

优点:

- 最像当前成功的简易方案
- 迁移成本低
- 猫识别最稳

## 方案 2 — SVG 像素猫极简重绘

做法:

- 用更少像素重新设计猫
- 强调轮廓和眼型
- 颜色压到 2-3 层

优点:

- 可以保持 SVG 统一缩放
- 更适合后续响应式

风险:

- 需要重新找一版“足够像猫”的造型

## 我的推荐

当前阶段推荐优先级:

1. `ASCII 主体 + SVG 外壳`
2. `极简 SVG 猫作为实验分支`
3. `放弃当前精细像素卡片方案`

## 实现建议

## P0

- 保留现有 `CompanionSprite` 作为猫主体
- 增加 SVG 气泡容器
- 增加 SVG 状态点
- 增加 Hover / Click 反馈框

## P1

- 实验一版极简 SVG 猫
- 对比它和当前 ASCII 主体谁更像猫

## P2

- 如果极简 SVG 猫识别度足够，再考虑替换
- 否则长期维持“猫用 ASCII，外壳用 SVG”

## 预览验证标准

看预览时，不要只看“精不精细”，而要看这四件事:

1. 缩小到 Header 尺寸后，第一眼像不像猫
2. 远看是不是仍然干净
3. 气泡和状态有没有喧宾夺主
4. 和页面 Header 放在一起时，会不会像多了一个功能块

## 最终结论

Header SVG 的正确方向，不是把咪兔做成更细的小插画。

而是:

- 让猫更简
- 让结构更轻
- 让 SVG 更像一层终端风语法
- 让用户先看到“那是一只猫”，再看到“它有一点点游戏感”

这才是适合 Header Companion 的 SVG 收敛方向。
