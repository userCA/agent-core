# 18 — 目标与防疲劳系统

## 目标

为咪兔建立一套既能引导玩家持续回来、又不会制造负担和焦虑的目标系统。

这份文档要解决五个问题:

1. 玩家每天回来时，应该知道自己能做什么
2. 系统怎样给轻目标，而不是打卡任务
3. 用户错过一天、一周，应该发生什么
4. 如何防止目标系统把陪伴做成 KPI
5. 如何让长期活跃来自感情和变化，而不是被迫上线

## 核心原则

| 原则 | 说明 |
|------|------|
| 目标是邀请，不是命令 | 给方向，不给压力 |
| 错过可恢复 | 目标可以失效，但不造成永久损失 |
| 完成感来自关系 | 奖励优先是情感反馈、回忆、外观变化 |
| 任务必须贴合真实使用 | 优先围绕提问、调工具、陪伴、回归、时段事件 |
| 不做全勤绑架 | 连续上线可以奖励，但不能成为唯一最优路线 |
| 少而明确 | 每天 2-3 个目标，每周 1-2 个目标即可 |

## 目标系统的定位

咪兔的目标系统，不是 MMO 的每日清单，也不是手游的体力任务。

它更像:

- 今天咪兔想和你一起做点什么
- 这个星期你们之间可能发生什么
- 如果你愿意，顺手完成就会留下痕迹

正确体验:

```text
"诶，这个目标刚好顺手做了。"
```

错误体验:

```text
"为了拿奖励我得上线把这几项清完。"
```

## 四层目标结构

目标系统分四层:

### 1. 即时小期待

不正式列为任务，只通过咪兔短气泡表达。

示例:

- "如果你愿意，再摸摸我一次也可以喵。"
- "今晚要是再见到你，我会记住的。"
- "要不要喂我点东西？"

作用:

- 把硬目标柔化成陪伴邀请
- 减少系统命令感

### 2. 每日目标

回答"今天适合做什么"。

特点:

- 数量少
- 低负担
- 10 分钟内自然可完成
- 奖励轻但明确

### 3. 每周目标

回答"这一周你们之间会留下什么"。

特点:

- 节奏慢
- 更偏回忆和收藏
- 不要求天天推进

### 4. 隐藏目标

回答"你们之间还有什么没被写出来的小秘密"。

特点:

- 不明示
- 发现时有惊喜
- 强化角色真实感

## 每日目标设计

## 数量

每日目标固定 2-3 条。

推荐结构:

- 1 条工作型
- 1 条陪伴型
- 0-1 条时段 / 情境型

这样可以兼顾:

- 高频工作用户
- 偶尔陪伴用户
- 喜欢探索彩蛋的用户

## 每日目标池

### A. 工作型目标

围绕正常使用产生，不额外加戏。

示例:

| 目标 | 条件 | 奖励建议 |
|------|------|---------|
| 成功调用工具 3 次 | `tool_success >= 3` | `spark +1` |
| 修复 1 次失败 | `error_recovery >= 1` | `spark +1` |
| 连续专注工作 20 分钟 | `focus_session >= 20min` | 休息提醒气泡 + `spark +1` |
| 尝试一种新功能 | `first_use_today` | `spark +1` |

### B. 陪伴型目标

围绕人与咪兔的关系行为。

示例:

| 目标 | 条件 | 奖励建议 |
|------|------|---------|
| 摸摸咪兔 2 次 | `pet_count >= 2` | `snack +1` |
| 喂它一次 | `feed_count >= 1` | bond 小幅增长 |
| worried 时安抚它一次 | `comfort_success >= 1` | `snack +1` + 专属气泡 |
| 和它聊一句"谢谢" | `gratitude_detected` | 品种专属回应 |

### C. 时段型目标

利用 [09-daily-rhythm.md](file:///Users/yuanbaishu/pythonProject/agent-core/docs/companion-design/09-daily-rhythm.md) 的时间段系统，让一天内不同时间有不同感受。

示例:

| 目标 | 条件 | 奖励建议 |
|------|------|---------|
| 傍晚和咪兔见一面 | `period == EVENING` 且有交互 | `memory_shard +1` |
| 深夜陪它 1 次 | `period == LATE_NIGHT` 且有 prompt | 专属回忆文本 |
| 午间回来看看它 | `period == NOON` 且打开 `buddy` 面板 | `snack +1` |

## 每日目标生成规则

每日目标不能纯随机，必须带一点个性化。

### 生成优先级

1. 基于昨天或最近行为
2. 基于咪兔当前状态
3. 基于用户 STYLE 倾向
4. 基于时段和稀有事件
5. 最后才从通用池随机

### 生成示例

如果用户最近大量使用工具:

- 优先给工作型目标
- 少给闲聊型目标

如果咪兔最近处于 `sleepy`:

- 更容易出现"来看它一眼"、"喂它一下"这类温柔目标

如果用户是 `COMPANION` 风格:

- 提高对话型、陪伴型目标权重

如果用户是 `TECH_PARTNER`:

- 提高错误恢复、连锁成功、专注工作类目标权重

## 每日目标模板

### 标准模板

```text
今日目标
[ ] 成功调用工具 3 次
[ ] 摸摸咪兔 2 次
[ ] 傍晚回来看看它
奖励: snack +1, spark +1
```

### 完成后的展示

```text
今天的小约定完成了。
"我有被好好放在今天里面喵。"
```

要求:

- 不用夸张庆祝文案
- 更像咪兔记住了这一天

## 每周目标设计

每周目标的功能不是催签到，而是制造"共同度过一周"的感受。

## 数量

每周固定 1-2 条。

## 每周目标类型

### A. 关系型

示例:

- 这周摸摸咪兔 10 次
- 这周喂它 3 次
- 这周完成 1 次深夜陪伴

### B. 工作型

示例:

- 这周完成 20 次成功工具调用
- 这周完成 3 次错误恢复
- 这周尝试 2 种不同类型工具

### C. 探索型

示例:

- 这周触发 1 次隐藏互动
- 这周查看一次 `memory` 面板
- 这周解锁 1 条品种专属气泡

### D. 时间型

示例:

- 在 3 个不同时间段见到咪兔
- 本周经历一次傍晚 zoomies
- 本周午间回来看看它两次

## 每周目标奖励

每周奖励不应主要给数值，而应给:

- `memory_shard`
- 房间线稿
- 一句周总结
- 小装饰
- 回忆卡

推荐形式:

```text
本周小约定完成
[获得] memory_shard +2
[新增] 房间角落: 小灯
```

## 隐藏目标设计

隐藏目标的价值，是让系统看起来像有秘密，而不是只有公开 checklist。

## 原则

- 不提供明示列表
- 首次发现时有惊喜
- 奖励小而独特
- 更重表演和回忆，不重数值

## 隐藏目标示例

| 隐藏目标 | 条件 | 奖励 |
|---------|------|------|
| 深夜摸摸 | 03:00-03:05 `/pet` | 深夜专属回应 |
| 安静同步 | 输入 `...` 三次 | 一条复制你语气的回忆 |
| 完美修复 | 连续 5 次 error recovery 成功 | 稀有鼓励气泡 |
| 小小日常 | 连续 3 天午间回来看看它 | 一个极小角落装饰 |
| 开发搭子 | 一天内同时完成工作型 + 陪伴型 + 时段型目标 | 纪念卡标题 |

## 防疲劳系统

目标系统要成立，防疲劳必须是它的一部分，而不是补丁。

## 疲劳来源

咪兔最容易出现的疲劳点有五类:

1. 任务太多
2. 奖励太碎
3. 漏做就亏
4. 连续上线收益最高
5. 内容看起来永远做不完

这五类都必须被设计主动压制。

## 防疲劳规则

### 规则 1 — 每日目标永远不超过 3 条

宁可目标少，也不要让玩家产生"今天还有一堆没清"的感觉。

### 规则 2 — 目标必须贴近真实使用

禁止出现这类目标:

- 连续点击 20 次
- 喂食 10 次
- 刷某个动作 15 次
- 必须打开 4 个面板

允许出现的目标应该都能在自然使用里完成。

### 规则 3 — 目标错过不产生永久损失

错过一个每日目标:

- 不扣 bond
- 不影响主线成长
- 不影响未来目标池

只意味着:

- 今天少拿一点轻资源
- 少留下一条小回忆

### 规则 4 — 连续活跃奖励是加分项，不是主线

`streak_7` 和 `streak_30` 可以存在，但奖励设计必须谨慎。

建议:

- 奖励回忆、纪念语、轻装饰
- 不要给压倒性的成长加速

否则用户会觉得:

```text
不连登就亏太多
```

### 规则 5 — 自动休息期

当用户连续多天高强度完成目标后，系统应主动降低负担。

示例:

- 近 5 天完成率 > 80%
- 次日只生成 2 条更轻的目标
- 奖励正常，不因为目标变少而亏

这会让系统看起来像在体谅用户。

### 规则 6 — 回归期提升温柔度

当用户离开几天后回归:

- 目标数量先减到 1-2 条
- 优先生成低门槛陪伴型目标
- 给一点回归补偿

目标文案也应更柔和:

```text
"今天回来看看我就很好了。"
```

## 错过与恢复机制

## 错过每日

结果:

- 该日目标过期
- 不保留到第二天
- 不额外惩罚

但可以触发一条轻叙事:

```text
"昨天没见到你，不过今天也来得及喵。"
```

## 错过每周

结果:

- 周目标重置
- 若已完成一部分，可折算成轻回忆或少量资源

建议:

| 完成进度 | 折算 |
|---------|------|
| < 30% | 无折算或仅一条安慰气泡 |
| 30-70% | `snack +1` 或一句周总结 |
| > 70% | `memory_shard +1` 或半完成纪念卡 |

这样能降低"差一点就白做了"的挫败感。

## 回归周设计

如果用户离开 7 天以上，回归后的第一周应进入"回归周"模式。

### 特征

- 每日目标减少
- 每周目标仅 1 条
- 奖励略微提高
- 目标以重连关系为主

### 示例

```text
回归小约定
[ ] 今天和咪兔打个招呼
[ ] 如果愿意，摸摸它一次
奖励: snack +2
```

## 目标文案规范

目标文案不是系统命令，应该像邀请或约定。

## 语气规范

推荐:

- "今天可以试试..."
- "如果愿意..."
- "回来看看它"
- "陪它待一会"

避免:

- "必须完成"
- "立即领取"
- "今日未完成"
- "还差 7 次"

## 文案层级

| 层级 | 语气 |
|------|------|
| 标题 | 中性、轻柔 |
| 目标本身 | 清晰简短 |
| 完成反馈 | 温暖、记住这一天 |
| 错过反馈 | 理解、无责备 |

## 完成感设计

玩家完成目标后，应该感到"今天被记住了"，而不是"进度条涨了"。

## 完成反馈顺序

1. 咪兔动作
2. 一句短气泡
3. 奖励结算
4. 可选回忆沉淀

示例:

```text
咪兔轻轻碰了一下你的光标。
"今天陪得很好喵。"
[获得] snack +1
```

## 不完成反馈顺序

不应出现失败红字或损失提示。

示例:

```text
"昨天的小约定没关系，今天重新开始就好。"
```

## 与 bond / 奖励系统的关系

目标系统不是独立主线，它只是帮助用户更容易走进 bond 和回忆。

## 关系图

```text
目标
  → 引导发生自然互动
  → 互动触发情绪 / 奖励 / milestone
  → 推动 bond 与长期收藏
```

目标不应该直接负责:

- 大量发 bond
- 大量发资源
- 强推用户上线

## 分层奖励建议

| 目标层级 | 奖励重心 |
|---------|---------|
| 每日 | `snack`, `spark`, 短气泡 |
| 每周 | `memory_shard`, 房间线稿, 周总结 |
| 隐藏 | 回忆文本, 稀有动作, 小装饰 |
| streak / 纪念 | `ribbon`, 纪念卡, 特殊称呼 |

## 与现有系统的衔接

| 系统 | 作用 |
|------|------|
| `BondGrowth` | 目标完成推动互动，但不替代 bond 主增长 |
| `DailyRhythm` | 决定时段型目标与回归气氛 |
| `RewardEngine` | 目标完成后的资源与装饰结算 |
| `MilestoneTracker` | 周目标和隐藏目标的结果沉淀成回忆 |
| `EmotionFSM` | 决定咪兔在目标完成/错过后的情绪表达 |
| `UI/UX` | 通过 `goal` 面板和轻气泡展示，不打断主流程 |

## 平衡目标

理想状态下:

- 新用户第一周不会被任务吓退
- 中度用户每天 5-10 分钟自然就能完成大部分目标
- 高活跃用户不会因为全清目标而收益爆炸
- 断更用户回来后不会因为漏太多而失去动力
- 长期玩家会觉得自己和咪兔共同度过了很多天，而不是刷了很多任务

## 最终体验

好的目标系统，应该让用户每天回来时产生这样的感觉:

- "今天它想和我做点什么。"
- "我做不完也没关系。"
- "顺手完成的时候，会觉得这一天被记住了。"
- "我不是在给系统打卡，我是在和咪兔一起过日子。"

这就是咪兔目标与防疲劳系统真正要做到的事。
