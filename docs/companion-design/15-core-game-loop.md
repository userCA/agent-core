# 15 — 核心玩法循环

## 目标

把咪兔从"有设定的终端风格伴侣"推进为"真的能养、能玩、能长期留下来"的网页 / App 养成游戏。

这份文档回答四个问题:

1. 玩家每次打开网页 / App 时，到底在玩什么？
2. 玩家为什么愿意继续陪它、养它？
3. 现有的情绪/亲密度/里程碑系统，如何串成闭环？
4. 如何在黑白、点线、极简条件下，做出有风格的游戏世界？

## 设计原则

| 原则 | 说明 |
|------|------|
| 工作即养成 | 用户正常提问、调用工具、写代码，本身就是主玩法，不额外打断 |
| 轻操作，高反馈 | 单次互动 <= 3 秒，但反馈要明显：动作、气泡、资源、记忆至少命中一层 |
| 少资源，强意义 | 不做复杂经济系统，只保留少量可感知资源 |
| 不惩罚离开 | 离开可触发情绪和叙事，但不制造负罪感，不掉大等级 |
| 每层都有可见兑现 | 数值增长必须落到外观、房间、收藏、称呼、行为变化上 |
| 极简不空 | 黑白终端风不是省成本，而是世界观语言：点、线、框、闪烁都带情绪 |

## 一句话循环

```
工作 / 陪伴
    ↓
触发咪兔反应
    ↓
获得少量资源 / 记忆 / bond
    ↓
解锁新动作 / 新互动 / 新外观
    ↓
更愿意继续回来陪它
```

## 四层循环

### 1. 分钟循环 — "现在就能摸到反馈"

用户每次输入、调用工具、空闲、安抚、喂食，都应在数秒内得到反馈。

```
用户提问 / 使用工具 / 点按摸摸 / 点按喂食
        ↓
EmotionFSM / DailyRhythm / BreedProfile 判定
        ↓
输出 Reaction:
  - 动画变化
  - 气泡一句话
  - 亲密度微增
  - 掉落轻资源
        ↓
用户觉得: "它有在陪我"
```

### 2. 日循环 — "今天可以做什么"

每天都应有 2-3 个轻目标，促使玩家在工作主线外多看它一眼。

示例:

| 类型 | 目标例子 | 奖励 |
|------|---------|------|
| 陪伴 | 今天摸摸咪兔 3 次 | `snack +1` |
| 工作 | 今天完成 5 次成功工具调用 | `spark +2` |
| 时段 | 在傍晚 18:00-20:00 见到 zoomies | `memory_shard +1` |
| 关怀 | 咪兔 worried 时安抚它 1 次 | `bond +5` |

### 3. 周循环 — "这一周有什么变化"

周循环负责中期留存，不靠签到压迫，而靠"本周共同经历"。

示例:

| 主题 | 条件 | 兑现 |
|------|------|------|
| 工作周报 | 本周完成 20 次工具成功 | 一句总结气泡 + 回忆页 |
| 夜猫子周 | 本周深夜见面 3 次 | 深夜限定对话 |
| 陪伴周 | 本周 /pet 累计 15 次 | 专属动作或小装饰 |
| 探索周 | 触发 2 个隐藏互动 | 图鉴页 + 彩蛋记录 |

### 4. 长期循环 — "这只猫越来越像我的猫"

长期循环的核心不是刷数值，而是留下痕迹。

```
日常互动
  → 里程碑
  → bond 提升
  → STYLE 固化
  → kitten/adult/soulmate 视觉演化
  → 回忆墙 / 图鉴 / 名片
```

用户最终追求的不是"满级"，而是:

- 看到这只咪兔被自己养出独特性
- 拥有一串只有彼此才懂的回忆
- 在产品里形成稳定的陪伴节奏

## 主循环结构

## Phase 1 — 观察

玩家先看到咪兔当前状态。

状态来源:

- `emotion`: neutral / happy / worried / sleepy / annoyed / excited
- `energy`: 精力高低
- `bond`: 当前亲密等级
- `need`: 当前想要什么，例如"想玩"、"困了"、"想吃鱼"
- `period`: 晨间 / 午间 / 傍晚 / 深夜

界面里的观察必须足够轻:

```text
[咪兔] (=-.-=)  sleepy
心情: ..o..
亲密: FRIEND
想法: "好困，但是你来了的话也可以再撑一会"
```

这一层的意义不是展示数据，而是给玩家一个"我该不该理它一下"的判断。

## Phase 2 — 选择

玩家有两种玩法入口:

### A. 工作型入口

不主动进入小游戏，继续正常工作:

- 提问
- 调工具
- 调试
- 写代码
- 看结果

系统把这些工作行为自动解释成"陪伴行为"。

### B. 互动型入口

玩家主动触发轻交互入口:

| 入口 | 作用 | 时长 |
|------|------|------|
| `pet` | 摸头、安抚、推进情感 | 1s |
| `feed` | 喂食，消耗零食或鱼 | 1s |
| `play` | 短互动，消耗精力换快乐 | 2-3s |
| `buddy` | 打开伴侣面板 | 1s |
| `goal` | 查看今日轻目标 | 1s |
| `memory` | 看回忆、相册、图鉴 | 2-5s |

原则: 不做需要离开网页 / App 主流程的重面板，所有入口都应"点一下就有结果"。

## Phase 3 — 反馈

每次选择后，至少触发 1 层即时反馈，理想情况触发 2-3 层。

### 即时反馈层

| 层 | 示例 |
|----|------|
| 动作 | 耳朵竖起、踩奶、翻肚皮、炸毛 |
| 文本 | "这次修好了！我就知道你行喵" |
| 数值 | `bond +2`, `spark +1` |
| 收藏 | 记录一条回忆、解锁一条图鉴 |

### 反馈顺序

```text
先动作
再短气泡
最后才是数字变化
```

原因: 角色感必须先于系统感，咪兔不能看起来像一个挂着猫皮的数值面板。

## Phase 4 — 沉淀

一次互动结束后，结果进入长期存储:

- `bond_score`
- `style_observer`
- `milestone`
- `memory log`
- `daily goal progress`
- `weekly summary progress`

沉淀后的信息不能只躺在数据库里，必须能回看:

- `memory` 面板看成长时间线
- `buddy` 面板看当前状态和称呼变化
- `album` 面板看成长截图或 ASCII 相册
- 周总结气泡回顾本周共同经历

## 三类核心动机

### 1. 陪伴动机

玩家想理它，是因为它"像活着一样"。

兑现方式:

- 情绪切换明显
- 品种口吻稳定
- 深夜、回归、连续失败时有情境反应
- bond 提升后称呼和态度变化

### 2. 养成动机

玩家想继续养，是因为它会变。

兑现方式:

- kitten → adult → soulmate
- 配饰增加
- 专属动作解锁
- 房间/角落逐渐丰富
- 回忆和图鉴不断填满

### 3. 收集动机

玩家想留下来，是因为系统不断产生可收藏的痕迹。

兑现方式:

- milestone 卡片
- 彩蛋记录
- 品种专属事件
- 每周回顾
- 成长相册

## 轻资源系统

不引入金币、钻石这类破坏氛围的通用货币，只保留和终端风格世界一致的轻资源。

| 资源 | 含义 | 获取 | 用途 |
|------|------|------|------|
| `snack` | 零食/鱼干 | 每日目标、钓鱼、陪伴事件 | `feed`、安抚、触发专属反应 |
| `spark` | 情绪火花 | 工具成功、连锁互动、里程碑 | 解锁装饰、特效、房间线稿 |
| `memory_shard` | 回忆碎片 | 周目标、周年、特殊时段事件 | 拼出回忆页、纪念卡 |
| `ribbon` | 装饰织带 | 稀有事件、品种专属奖励 | 解锁围巾、项圈、角落摆件 |

约束:

- 资源种类最多 4 个
- 单次掉落量很小，避免刷数值感
- 资源更像"情感媒介"而非传统货币

## 资源循环

```
工作成功 / 陪伴互动 / 时段彩蛋
        ↓
获得少量 snack / spark / shard
        ↓
喂咪兔 / 解锁小摆件 / 补完回忆页
        ↓
咪兔外观、房间、反应更丰富
        ↓
继续互动的欲望上升
```

## 目标系统

里程碑解决"发生过什么"，目标系统解决"接下来做什么"。

### 每日目标

特点:

- 每天 2-3 条
- 10 分钟内可完成
- 不要求强上线，不做全勤焦虑

示例:

```text
今日目标
[ ] 成功完成 3 次工具调用
[ ] 摸摸咪兔 2 次
[ ] 在 NIGHT 时段和它见一次面
奖励: snack +1, spark +1
```

### 每周目标

特点:

- 1-2 条
- 和本周互动风格有关
- 奖励偏回忆或装饰，不给大量数值

示例:

```text
本周小约定
[ ] 这周和咪兔一起经历一次深夜调试
[ ] 触发 1 次 breed exclusive bubble
奖励: memory_shard +2, 新边框线稿
```

### 隐藏目标

不写清楚，只通过"好像发生了什么"让用户自己发现。

例如:

- 连续 3 次深夜 /pet
- 一天内 10 次成功修复 error
- 在傍晚 zoomies 时间陪它玩

## 奖励优先级

奖励的感知强弱从高到低:

1. 新动作 / 新气泡 / 新称呼
2. 外观变化 / 房间变化 / ASCII 特效
3. 回忆卡 / 图鉴条目 / 相册
4. 轻资源
5. 单纯 bond 数值

设计要求:

- 不要让数值成为唯一奖励
- 资源只是"打开情感反馈的钥匙"
- 每次阶段升级都要给看得见的变化

## 失败与恢复

养成游戏必须允许状态起伏，但不能制造压力。

### 允许的失败

- 咪兔心情变差
- 精力降低，变 sleepy
- 连续失败时 worried / annoyed
- 某些目标自然过期

### 不允许的失败

- bond level 降级
- 关键内容永久错过
- 离开几天后被系统惩罚
- 因为没喂没摸就失去角色好感

### 恢复节奏

```text
一次安抚
  或一次成功工作
  或一次回归见面
→ 应该就能把关系拉回温暖状态
```

这条规则比任何数值平衡都重要: 咪兔是陪伴角色，不是情绪勒索器。

## 终端风的世界兑现

黑白、点线、低分辨率，不是简陋，而是这个世界的语言。

### 符号语义

| 符号 | 语义 |
|------|------|
| `.` | 微弱情绪、安静、呼吸 |
| `o` | 活力、注意力、可互动点 |
| `*` | 稀有、惊喜、闪亮 |
| `-` | 困倦、停顿、休息 |
| `|` / `/` / `\` | 房间线稿、边界、支架 |
| `[]` | 面板、容器、收纳 |
| `_` | 地面、安全感、停靠 |

### 风格目标

不是"可爱贴图 UI"，而是"一团活物住在由点线构成的终端角落里"。

### 兑现方式

- `spark` 不显示为金币，而显示为散开的 `*`
- 房间升级不是换皮肤，而是页面角落里多一条线框、一个窝、一盏灯
- 节日奖励不是华丽弹窗，而是某条线、某个符号、某种闪烁频率变了

## 推荐实现顺序

### P0 — 先把闭环跑起来

1. 工作事件 -> bond / spark / bubble 的稳定产出
2. `goal` 面板 + 每日轻目标
3. `feed` 交互 + `snack`
4. `buddy` 面板显示当前 emotion / bond / 今日目标

### P1 — 把成长看得见

1. kitten / adult / soulmate 三阶段 ASCII 帧
2. milestone 回忆页
3. weekly summary 周总结气泡
4. 品种专属奖励和 exclusive bubble

### P2 — 把世界搭起来

1. 页面角落房间线稿
2. 装饰物解锁
3. 图鉴 / 相册 / 纪念卡
4. 隐藏目标与彩蛋合集

## 与现有系统的衔接

| 现有系统 | 在主循环中的位置 |
|---------|----------------|
| `EmotionFSM` | 分钟循环的即时状态反馈 |
| `DailyRhythm` | 日循环的时段变化、目标设计依据 |
| `BondGrowth` | 长期循环的纵向成长 |
| `STYLE` | 长期循环的横向分化 |
| `MilestoneTracker` | 负责把日常事件沉淀成回忆 |
| `InteractionChain` | 提升短时操作的戏剧性反馈 |
| `MiniGame` | 主循环之外的调味玩法，不替代主循环 |

## 最终体验

理想中的咪兔，不是一个等你点击的宠物挂件，而是一只会在你工作时安静陪着你、在你失败时露出担心、在你坚持时慢慢长大的终端风格生物。

用户打开网页 / App 时，应该自然产生这四种感受:

1. "它今天状态怎么样？"
2. "我顺手理它一下吧。"
3. "诶，它真的记得我们。"
4. "这只咪兔已经越来越像我的那只了。"
