## 2026-05-18

### 问题 18：agent-core 架构优化（对标 demo/core）

- **背景**：当前 agent-core 框架与 demo/core（TypeScript）相比存在三处架构差距：工具系统无可插拔抽象、资源加载无统一机制、系统提示词由各 scene 自行拼接
- **目标**：以 agent_core 库级别优化为主，scene 层仅做必要适配，保持向后兼容

#### 18.1 工具系统可插拔性

- **方案**：引入 `FileOperations` / `BashOperations` Protocol，解耦工具实现与具体 IO 后端
- **核心新增**：
  - `agent_core/tools/operations.py`：`FileOperations`、`BashOperations` Protocol + `FileInfo`、`BashResult`
  - `agent_core/tools/operations_local.py`：`LocalFileOperations`、`LocalBashOperations` 本地实现
  - `agent_core/tools/mutation_queue.py`：`FileMutationQueue` 按路径串行化并发文件修改
  - `agent_core/tools/render.py`：`ToolRenderer` Protocol + `RenderedOutput`，支持前端定制显示而不影响 LLM 文本
  - `agent_core/tools/local/edit.py`：基于 `FileOperations.edit()` 的精确文本替换工具
  - `agent_core/tools/truncate.py`：智能截断工具（head/tail/line）
- **适配**：`read` / `write` / `bash` / `ls` / `grep` / `find` 全部迁移至 Protocol
- **向后兼容**：`ToolResult` 新增 `display`（默认 None）、`ToolDefinition` 新增 `renderer`（默认 None）、`ToolContext` 新增 `mutation_queue`（默认 None）

#### 18.2 资源发现与加载

- **方案**：统一 `ResourceLoader` 负责 skills、prompts、themes、context files、extension specs 的发现与加载
- **核心新增**：
  - `agent_core/resources/loader.py`：`ResourceLoader`，搜索路径优先级：显式 extras → `<cwd>/.pi/{type}/` → `~/.pi/agent/{type}/` → 环境变量
  - `agent_core/resources/types.py`：`Skill`、`PromptTemplate`、`Theme`、`ContextFile`、`ExtensionSpec`、`SourceInfo`、`ResourceDiagnostic`
  - `agent_core/resources/diagnostics.py`：`ResourceDiagnostics` 收集器，支持 warning / error / collision
  - `agent_core/resources/skills.py`：从旧 `agent_core.skills` 迁移，增强 `SourceInfo` 和诊断
  - `agent_core/resources/prompts.py`：YAML frontmatter 提示模板加载
  - `agent_core/resources/themes.py`：JSON 主题加载
  - `agent_core/resources/context_files.py`：向上遍历加载 `AGENTS.md` / `CLAUDE.md`，`.git` 为边界
  - `agent_core/resources/extensions.py`：`ExtensionSpec` 发现（不动态导入）
- **扩展加载器**：`agent_core/extensions/loader.py`：`ExtensionLoader` 支持从 specs 和 entry_points 加载
- **向后兼容**：`agent_core.skills` 保留功能但发出 `DeprecationWarning`，引导使用 `agent_core.resources`

#### 18.3 系统提示词构建

- **方案**：`SystemPromptBuilder` 动态构建系统提示，支持分段组装和扩展介入
- **核心新增**：
  - `agent_core/prompts/builder.py`：`SystemPromptBuilder.build()` 返回 `SystemPrompt`，按顺序生成 sections：base → tools → guidelines → tool_guidelines → context_files → skills → meta
  - `agent_core/prompts/guidelines.py`：基于激活工具名生成 lambda 规则（如 read/write 工具的格式规范）
  - `agent_core/prompts/snippets.py`：从 tool description 提取摘要（优先 `prompt_snippet`，次选首句）
- **扩展钩子**：`Extension` Protocol 新增 `on_before_agent_start(self, ctx, system_prompt)`，`ExtensionRunner` 新增 `before_agent_start()`
- **Scene 层迁移**：
  - 删除 `scene/cli/system_prompt.py`、`scene/http_sse/system_prompt.py`、`scene/voice_ws/system_prompt.py`
  - 三个 `chat_assistant.py` 全部改用 `SystemPromptBuilder` + `ResourceLoader`
  - `Skill` 类型迁移至 `agent_core.resources.types.Skill`，`_expand_skill_command` 使用 `skill.source.origin` / `skill.source.base_dir`

#### 18.4 合并冲突处理

- **问题**：feature 分支基于 HITL 之前的 main，合并时 `agent_core/core/tool_runner.py` 出现冲突（HITL 的 `on_update` 流式更新 vs 优化的 `mutation_queue`）
- **修复**：`_run_single_tool` 同时接受 `mutation_queue` 和 `on_update` 两个可选参数，`ToolContext` 同时传入两者
- **遗留问题**：main 的 HITL 提交完全重写了 `scene/*/chat_assistant.py`，导致 feature 分支的 scene 迁移在合并中被覆盖。合并后手动重新迁移。
