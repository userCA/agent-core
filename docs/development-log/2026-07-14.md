### 自我审查结果

初版分析 33 项，经 grep 核实实际调用情况后，**27 项是不必要的**，仅 6 项是真正的问题：

**我搞错的（不是问题）：**
- KnowledgeBase.add 阻塞事件循环 → scene 已用 `add_async()`
- Companion `last_active_at` 多用户覆盖 → 是实例属性，非全局
- MemoryStore 缺 update/list → 两处均未在任何调用方使用

**过度设计（无明确需求）：**
Memory 去重/质量过滤、Skill Evolution 持久化标记、Collector 任务级判定、SkillEvolutionStore 接口补全、ToolRegistry enable/disable、Retrieval Reranker、成本追踪、结构化日志/Metrics、Provider 熔断、HealthChecker、事件补充、AgentState 验证优化、Sequential 轮询优化、限流、多租户隔离——均无实际调用方或需求反馈。

**真正需要做的（6项）：**
1. P0: Skill Evolution 预算计算 bug（`agent.py:250`）
2. P0: Validation Gate 中文分词（`\w+` 不匹配中文）
3. P1: Observability LLM 调用追踪（`trace_llm_call()` 零调用方）
4. P1: Loop mid-run compaction（仅 overflow 时压缩）
5. P1: MemoryExtension 改为提取用户画像而非存原始消息（当前存的是原始用户消息文本，应改为 LLM 提取用户偏好/习惯/背景等画像事实）
6. P2: KnowledgeBase.retrieve 预加载索引（视文档量）

**教训**：
1. 分析时应先 grep 确认实际调用方和需求量，再判断是否是问题。"可能有用"不是优化的理由。
2. 理解一个模块的定位（做什么）比看它"缺什么"更重要。MemoryExtension 是用户画像/RAG 系统，不是对话消息的副本存储。
