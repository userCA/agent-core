## #7 前端 UI/UX 全面审查与优化（ui-ux-pro-max）

**问题**：
- 流式输出过程中思考内容与后续文本"一起闪现"——`handleFlush` 在 `isActive=true`（raw text）和 `isActive=false`（Markdown）之间频繁切换，`marked.parse` + `DOMPurify.sanitize` 每几百毫秒执行一次，造成视觉跳变和帧率下降
- `useTypewriter` 返回对象字面量导致 `StreamingMessage` 的 `useEffect` 每次渲染都执行
- `useAutoScroll` 依赖 `steps` 引用，步骤更新时过度触发滚动
- 无 `prefers-reduced-motion` 支持，逐字动画无法被系统级无障碍设置禁用
- 流式区域无 `aria-live`，屏幕阅读器无法感知 AI 生成内容
- `getDisplayableText` 非贪婪正则对嵌套 `<think>` 处理错误
- 全局使用等宽字体，长文本阅读体验差；大量使用 `[#]`、`[x]` 等 ASCII 符号作为 UI 图标

**修复**：
- `StreamingMessage`：流式过程中始终使用 raw text 模式，移除 `renderMarkdown` 调用；最终格式化由 `MessageBubble` 负责
- `useTypewriter`：`useMemo` 稳定返回对象，消除 `useEffect` 过度执行
- `ChatContainer`：`useAutoScroll` 依赖改为 `steps.length`
- `useTypewriter`：增加 `prefers-reduced-motion: reduce` 检测，一次性输出全部字符
- `StreamingMessage`：增加 `aria-live="polite"`、`aria-atomic="false"`、`aria-label`
- `StepsPanel`：折叠按钮增加 `aria-expanded` / `aria-controls`，详情区增加 `role="region"`
- `utils/think.ts`：`getDisplayableText` / `extractThinkSteps` / `stripThinkTags` 改为基于栈的解析器，正确处理嵌套 `<think>`
- `theme/tokens.css`：`body` / `.markdown-body` 改用系统无衬线字体，提升长文本阅读体验
- 新建 `components/shared/Icon.tsx`：统一 SVG 图标组件；替换 `StepsPanel`、`ToolStep`、`MessageBubble`、`Header`、`WelcomeScreen` 中的 `[#]`、`[x]`、`[!]`、`[%]`、`[+]`、`[-]` ASCII 符号
