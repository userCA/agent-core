# 2026-08-13

## Observability 链路去冗余 + 补全（turn span 事件驱动、去 SDK 双通道）

- **类型**: refactor / fix
- **背景**: 复盘 `agent_core/observability.py` 数据上报链路：SDK generation 与 OTLP span 双通道导致同一 LLM 调用在 Langfuse 面板出现两个同名 `agent.llm_call`（实证：1 次调用产出 2 条同名 span），且 `langfuse.observation.model` 属性名与 Langfuse SDK 常量（`langfuse.observation.model.name`）不一致。同时正常 turn 缺少 `agent.turn` span、LLM span 无 input/output、工具 span 无输入输出。

### 变更摘要

| 文件 | 说明 |
|------|------|
| `agent_core/observability.py` | 删 `_get_langfuse_client` / `_send_sdk_generation`（SDK 双通道）；删无效 `langfuse.observation.model`；`agent_span_attributes` 删零消费方冗余 key（`agent.session_id`/`agent.run_id`）；tool hook 删 `agent.provider`/`agent.model`；tool span 门控补 `tool.input`/`tool.output`/`tool.error`；`trace_llm_call` 门控补 `gen_ai.prompt`/`gen_ai.completion`；turn span 改为 harness 事件驱动（`_subscribe_turn_spans`）；删不再使用的 `trace_turn` context manager |
| `agent_core/core/loop.py` | 删 `trace_turn` 调用/import（事件驱动已覆盖全部 turn 路径，含 max_turns 分支）；`trace_llm_call` 三处传 `prompt=` 并在流后回填 `completion=` |
| `tests/core/test_observability.py` | 移除 `trace_turn` 测试；新增 `test_subscribe_turn_spans_creates_turn_span`；更新属性断言（无 `langfuse.observation.model`、无 `agent.session_id`/`agent.run_id`）；更新 hook 签名调用 |

### 关键决策

- **turn span 事件驱动**：`observe()` 通过 `harness.subscribe` 订阅 `TurnStart`/`TurnEnd` 事件创建/关闭 `agent.turn` span（`trace.set_span_in_context` + `_otel_context.attach`），LLM/tool span 自动继承为子节点。**不改 loop 控制流**，覆盖含 max_turns 强制收尾的所有 turn。
- **去 SDK 双通道**：Langfuse OTLP 已能按 `gen_ai.*` 映射 generation/usage/cost，SDK 补发是 `4138233` 在 usage 为空时的误判补救；单 span 保留 `langfuse.observation.type`/`usage_details` 作为自托管兼容属性。
- **内容上报门控**：`LANGFUSE_CAPTURE_CONTENT=1` 才写 `gen_ai.prompt`/`gen_ai.completion` 与 `tool.input/output/error`，默认关闭。
