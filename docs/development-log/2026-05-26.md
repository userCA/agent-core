## 2026-05-26

### 问题 22：agent-core 架构审查与全面优化

- **背景**：对 `agent_core/` 进行系统架构审查，发现 3 个 P0 / 3 个 P1 / 2 个 P2 问题。审查覆盖核心运行时、provider 层、工具层、会话层、扩展层。
- **目标**：逐项修复，提升框架的健壮性、类型安全性、可观测性和可扩展性。

#### 22.1 Provider 自动重试（P0）

- **需求**：LLM API 返回 429/500/502/503/504 时自动重试，带 exponential backoff + jitter
- **实现**：
  - `agent_core/providers/types.py`：`StreamError` 新增 `overflow: bool = False` 字段
  - `agent_core/providers/openai_provider.py`：新增 `_is_context_overflow()` 检测上下文溢出关键词
  - `agent_core/core/messages.py`：`AssistantMessage` 新增 `retryable_error` / `overflow_error` 标志
  - `agent_core/core/loop.py`：重试循环结构 —— buffered 模式，只对最终 attempt 发射事件
  - `agent_core/core/context.py`：新增 `max_retries: int = 3`、`retry_base_delay: float = 1.0`、`retry_max_delay: float = 60.0` 字段
  - `agent_core/core/agent.py`：构造参数透传 `max_retries`、`retry_base_delay`、`retry_max_delay`
- **关键设计**：流式事件只在最终 attempt 发射，避免 retry 过程产生重复的 assistant 消息
- **测试**：3 个新测试（retry 后成功 / 超过最大重试 / 不可重试错误不重试）

#### 22.2 上下文溢出自动压缩重试（P0）

- **需求**：LLM 返回 context overflow 错误时自动触发 compaction 并重试
- **实现**：
  - `agent_core/core/loop.py`：溢出检测 → 调用 `compact_callback` → 重新 `convert_to_llm` → retry
  - `agent_core/core/context.py`：新增 `compact_callback: CompactCallback | None` 字段
  - `agent_core/session/session.py`：`AgentSession.start()` 中注入 `_on_overflow_compact` 回调
- **关键设计**：如果 compact_callback 返回 False（无更多可压缩），不再重试

#### 22.3 Extension Hook 正式 API（P0）

- **需求**：原本通过 monkey-patching `agent._before_tool_call` 注入 hook，脆弱且无链式支持
- **实现**：
  - `agent_core/core/agent.py`：新增公共方法
    - `add_before_tool_call_hook(hook)` —— 返回 `{"block": True, "reason": "..."}` 阻止调用
    - `add_after_tool_call_hook(hook)` —— 返回 `{"result": {...}}` 改写结果
    - `add_transform_context_hook(hook)` —— 链式变换 LLM 消息列表
  - 内部 `_chain_before_hooks()` / `_chain_after_hooks()` / `_chain_transform_hooks()` 按注册顺序串接
  - 同步/异步 hook 自动检测：`inspect.isawaitable(result)` 判断
  - `agent_core/session/session.py`：移除 ~45 行 monkey-patching，改用公共 API
  - `tests/tools/test_aigc_creation.py`：更新测试使用新 API
- **关键设计**：`inject_metadata` 为合并语义（非覆盖），多个 hook 注入不同 key 不互相覆盖

#### 22.4 类型安全提升（P1）

- **需求**：`AgentLoopConfig` 大量字段类型为 `Any`，失去类型检查
- **实现**：
  - `agent_core/core/context.py`：新增类型别名 `BeforeToolCallHook`、`AfterToolCallHook`、`MessageDrainer`、`CompactCallback`
  - `AgentLoopConfig` 的 `tool_registry`、`before_tool_call`、`after_tool_call` 等字段全部改为精确类型
  - `agent_core/core/tool_runner.py`：`config: Any` → `config: AgentLoopConfig`
  - `agent_core/core/loop.py`：移除所有 `getattr(config, "field", default)` 兜底，改为直接 `config.field` 访问

#### 22.5 消息格式解耦（P1）

- **需求**：原本 `_default_convert_to_llm` 硬编码 OpenAI 格式，Anthropic 需要 OpenAI→Anthropic 二次转换
- **实现**：
  - `agent_core/providers/anthropic_provider.py`：新增 `_create_anthropic_converter()`，直接产出 Anthropic content-block 格式
  - `_is_anthropic_format()` 检测消息是否已为 Anthropic 格式，已转换则跳过
  - `create_message_converter()` 方法供 Agent 自动发现（通过 `hasattr` 检查）
  - `agent_core/core/agent.py`：provider 有 `create_message_converter` 则优先使用，否则用 OpenAI 默认格式
- **关键设计**：provider 可以选择产出 native 格式；Agent 自动检测，无需消费者配置

#### 22.6 MCP Tool 适配器（P1）

- **需求**：接入 MCP (Model Context Protocol) 工具服务器
- **实现**：
  - `agent_core/tools/mcp_tool.py`（新增）：
    - `MCPConnection`：管理 stdio / SSE 连接生命周期（`connect()` / `close()`）
    - `MCPToolAdapter`：把 MCP tool 映射为 agent_core `Tool` Protocol
    - `discover_mcp_tools()`：从 MCP server 发现所有工具

#### 22.7 OpenTelemetry 可观测性（P2）

- **需求**：为 agent 运行提供 OpenTelemetry trace
- **实现**：
  - `agent_core/observability.py`（新增）：
    - `observe(agent)` context manager：通过 before/after hook 注入 tracing
    - `trace_llm_call()` context manager
    - 无 OpenTelemetry 安装时优雅降级为 no-op

### 问题 24：设计债务清偿 —— 分层违规 + 类型空洞 + 死连接 + 鸭子类型

- **背景**：在问题 22/23 的基础上，对整体架构进行系统性审查，发现 4 个设计问题（P0-P3）
- **目标**：消除分层违规、收紧类型、接通断链、统一接口约定

#### 24.1 P0 — compact_callback 分层违规

- **问题**：`AgentSession.start()` 直接写入 `self._agent._compact_callback`（core 层私有字段），session 层不应碰 agent 私有属性
- **修复**：
  - `Agent.prompt()` / `continue_()` 新增 `compact_callback` / `trace_callback` 可选参数，透传到 `_run()` → `AgentLoopConfig`
  - `AgentSession` 在调用 `prompt()` / `continue_()` 时传入，不再写私有字段
  - 构造函数中的 `compact_callback` 保留作为默认值

#### 24.2 P1 — 类型空洞 + getattr 全面消除

- **问题**：`AgentState.messages` 和 `AgentContext.messages` 类型为 `list[Any]`，导致 `_default_convert_to_llm` 和 `_create_anthropic_converter` 中大量使用 `getattr(m, "role", None)` 防御
- **修复**：
  - `state.py` / `context.py`：`list[Any]` → `list[AgentMessage]`（discriminated union）
  - `ConvertToLlm` 类型签名：`list[Any]` → `list[AgentMessage]`
  - `agent.py` `_default_convert_to_llm` + `_user_content_to_openai`：全部 `getattr` 替换为 `isinstance` + 直接属性访问
  - `agent.py` `_handle_event`：`getattr(evt.message, "role", None)` → `isinstance(evt.message, AssistantMessage)`
  - `agent.py` `_chain_after_hooks`：`getattr(orig, "content", [])` → `orig.content`
  - `agent.py` `continue_`：`getattr(last, "role", None)` → `isinstance(last, (UserMessage, ToolResultMessage))`
  - `anthropic_provider.py` `_create_anthropic_converter`：全部 `getattr` 替换为 `isinstance`
  - `tool_runner.py`：`getattr(tool.definition, "timeout_seconds", None)` → `tool.definition.timeout_seconds`
  - core/ 目录仅剩 1 处 getattr（异常消息中构造人类可读字符串）

#### 24.3 P2 — mutation_queue 断链重连

- **问题**：`tool_runner.py` 两处硬编码 `mutation_queue = None`，`FileMutationQueue` 基础设施完整但从未接入运行时
- **修复**：
  - `AgentLoopConfig` 加回 `mutation_queue` 字段（上次清理误删——字段本身有价值，只是没被设置）
  - `Agent._run()` 创建 `FileMutationQueue()` 实例传入 config
  - `loop.py` `_execute_tools` 接收 `mutation_queue` 参数并传给 `tool_runner.execute_tools`
  - `tool_runner.py` `execute_tools` 接收参数，替换两处硬编码 `None`

#### 24.4 P3 — provider.stream 鸭子类型分支删除

- **问题**：`_stream_assistant` 中 `hasattr(stream, "__aiter__")` 分支处理，实际上所有 provider（Anthropic/OpenAI/Fake）的 `stream` 都是 `async def` + `yield`（async generator），不存在需要 `await` 的情况
- **修复**：去掉分支，统一 `async for evt in stream:`
- **注意**：`async def` 内使用 `yield` 返回 async generator，不可 `await`
