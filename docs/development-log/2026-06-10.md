### 修复的 bug

#### Bug 1: `forget` 静默吞 PermissionDeniedError
- **原因：** `except Exception: logger.warning(...)` 吞掉所有异常
- **修复：** 移除 try/except，异常直接传播
- **影响：** 调用方不知道删除失败，认为操作成功

#### Bug 2: 空 `session_id` 导致 `_resolve_api_key` 崩溃
- **原因：** `PurePosixPath("").parts[0]` 抛出 `IndexError`
- **修复：** 加 `if "/" in session_id` 守卫，不包含斜杠则直接回退默认 key

#### Bug 3: URL `/api/v1` 重复前缀
- **原因：** SDK 内部在所有路径前拼接 `/api/v1/...`，用户传入带 `/api/v1` 的代理 URL 会产生 `/api/v1/api/v1/...`
- **修复：** `url.removesuffix("/api/v1")` 自动去除

### 架构优化

#### P0: 统一 adapter 错误处理策略
- 全部 3 个 adapter（InMemory/Mem0/OpenViking）的所有方法（remember/recall/forget）统一为：异常直接抛出
- 移除不再使用的 `import logging` + `logger`
- 影响：`MemoryExtension` 需要自己处理异常（见下）

#### P1: MemoryExtension 错误处理
- `remember` 失败：单个失败不影响其他 pending，日志记录
- `recall` 失败：回退返回原始 `llm_messages`，不阻断对话
- `_pending` 上限 `_MAX_PENDING=100` 防止无界增长
- `transform_context` 中检查 `signal.is_set()` 支持取消
- 空 query 提前返回避免无效 API 调用

#### P2: InMemoryMemoryStore 异步安全
- 添加 `asyncio.Lock` 保护所有读写操作

### 已知限制

- OpenViking `recall` 使用 `find()` 搜索 `viking://user/memories`，返回的是记忆结构文档（.abstract.md/.overview.md），而非原始用户事实。这是 OpenViking `commit_session` 记忆提取管线的设计特性，不是 adapter bug。`search()` API 是 experimental 且当前服务版本不稳定。
- OpenViking `forget` 调用 `delete_session`，在共享 session 服务上需要 ADMIN/ROOT 权限
