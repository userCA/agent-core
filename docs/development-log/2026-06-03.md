## 详细记录

### 59-61. Bash 操作协议优化

参考 pi-mono 的 `BashOperations.exec(onData, signal)` 设计：
- `BashOperations.execute()` 增加 `on_data: Callable[[bytes], None]` 逐块推送
- `LocalBashOperations` 流式读取 stdout/stderr，每 4096 字节回调
- `signal: asyncio.Event` 传入，abort 时杀进程树（Linux: `kill(-pid, SIGKILL)`，macOS: `pkill -P` + `kill`）
- `start_new_session=True` 确保进程组隔离
- 超时后保留已捕获的部分输出，不再丢弃
- BashTool 集成 `truncate_head`（保留末尾，最新输出最有用）
- `commandPrefix`/`spawnHook` 支持沙箱环境初始化

### 62-64. 沙箱服务接入

- `SandboxQuota`: CPU/内存/磁盘/网络四维限制
- `SandboxBackend` Protocol: start/stop/health_check/restart 生命周期
- `DockerSandboxBackend`: 同时实现 SandboxBackend + FileOperations + BashOperations
  - 路径三区模型：`/mnt/output/`（读写）、`/tmp/`（临时）、系统目录（只读）
  - `docker run` 时注入 `--cpus`/`--memory`/`--network=none`
- `SandboxPolicyExtension`: 配额分配矩阵 + 危险命令正则拦截
- `SelfHealingExtension`: 即时修复（pip install）+ 增强错误提示

### 65. mutated_args + args_model

参考 pi-mono 的 "Mutate event.input in place" 设计：
- `on_before_tool_call` 可返回 `{"mutated_args": {...}}` 修改工具参数
- ExtensionRunner + _chain_before_hooks 均支持合并多个扩展的 mutated_args
- `ToolDefinition.args_model` 可指定 Pydantic 校验模型，tool_runner 在调用前自动校验

### 66-67. Agent 生命周期 hook

`BeforeAgentStart` hook 从 loop 移到 Agent._run()：
- 扩展可在 agent_loop 启动前注入 system_prompt 或前置 message
- loop.py 不再感知扩展存在，回归纯消息处理引擎

### 68-69. Agent 重构

参考 pi-mono Agent 设计：
- `pendingToolCalls: set[str]` 追踪执行中的工具调用
- `hasQueuedMessages()` 便捷查询
- `signal` property 公开 asyncio.Event
- `_handle_run_failure()` 创建结构化 AssistantMessage 并 emit AgentEnd
- `_create_loop_config()` 独立方法提取
- `AgentLoopConfig.provider` → `stream_fn` callable，loop 不依赖 provider 实例

### 70. ToolResultMessage tool_name 修复

**根因**：tool_runner.py 两处 `ToolResultMessage(...)` 构造漏传 `tool_name`。
实时 SSE 通过 `ToolExecutionEnd.tool_name` 正常，历史加载通过 `/session` API 返回 `"tool_name": null`，
前端 `loadMessages` 按 `tool_name` 匹配工具块失败 → 视频 block 不重建。

**修复**：两处补加 `tool_name=tool_call.name`。

### 73. tool_runner.py — 工具执行失败静默无日志

**根因**：`except Exception as exc:` 直接创建 ToolResult 返回，无 logger 调用（规则 8 违反）。
异常进了消息内容（模型可见），但生产环境完全无迹可查。

**修复**：添加 `logger.warning("Tool '%s' execution failed: %s", tool_call.name, exc)`。

### 74. observability.py — monkey-patching 内部 hook 列表

**根因**：`observe()` 直接操作 `agent._before_hooks`（insert(0)）和 `agent._after_hooks`（append），
finally 中整列表替换恢复。违反规则 7（API 迁移——monkey-patching 脆弱，并发不安全）。

**修复**：
- Agent 新增 `remove_before_tool_call_hook()` / `remove_after_tool_call_hook()` 公共方法
- observability 改用 `add_*_hook()` 注册，`remove_*_hook()` 清理

### 75. session.py — hasattr(result, "__await__") 不一致

**根因**：所有 hook 链使用 `inspect.isawaitable(result)`，但 session 的 listener 分派用了
`hasattr(result, "__await__")`，覆盖不完整（generator-based coroutine 不走 `__await__`）。

**修复**：改为 `inspect.isawaitable(result)`，与 agent.py 保持一致。

### 76. tool_runner.py — hook/校验异常日志级别过低

**根因**：before/after hook 失败和 args_model 校验失败使用 `logger.debug()`，不是正常操作，
应在 production 可见。

**修复**：3 处 `logger.debug` → `logger.warning`（before_tool_call hook、args_model 校验、after_tool_call hook）。

### 77. agnes_video_tool.py / mcp_tool.py — bare except 无日志

**根因**：`agnes_video_tool.py` 无 logger 定义，`except Exception as e: return ToolResult(...)` 
无任何日志。`mcp_tool.py` 的 `ping()` `except Exception: return False` 同样。

**修复**：agnes_video_tool.py 新增 `logger = logging.getLogger(__name__)`，3 处 bare except 添加 logger.warning/debug。
mcp_tool.py ping 添加 `logger.debug("MCP ping failed", exc_info=True)`。

### 78. knowledge/local_kb.py — 模型初始化非线程安全 + 静默 continue

**根因**：`_get_model()` 使用 `global _MODEL` + lazy init，无锁保护。`add()` 和 `retrieve()` 
可并发调用，双线程同时命中 `_MODEL is None` → 初始化两次。
`except Exception: continue` 在 retrieve 中跳过损坏 chunk 无日志。

**修复**：双重检查锁 `threading.Lock()`，chunk 加载失败添加 `logger.debug()`。

### 79. memory/retrieval extension — 重复的 system message 注入模式

**根因**：两个 extension 的 `transform_context` 中几乎相同的代码：
取 latest_user_text → 构建 body_lines → 创建 system_msg → 在 latest_user_index 处插入。
约 6 行重复（规则 1）。

**修复**：提取 `inject_system_message_at_latest_user()` 到公共工具函数，两个 extension 调用。

### 80. _llm_message_utils.py 移至 providers/

**根因**：文件在 `agent_core/` 根目录，包含 LLM 消息格式检查（`"role"`、`"content"` 键）。
规则 12 要求 provider 格式逻辑在 `providers/`。

**修复**：`agent_core/_llm_message_utils.py` → `agent_core/providers/llm_message_utils.py`，2 个 import 路径更新。

### 87. StreamingMessage contentRef 未绑定

### 88. session_store_dir 绝对路径

**根因**：`SessionManager` 默认 `session_store_dir="./sessions"` 依赖 `os.getcwd()`。从 `static/` 目录启动时 sessions 写入错误目录 → 200+ 历史会话"消失"。同样的问题（MCP `.mcp.json` 加载也依赖 cwd）导致连接器列表为空。

**修复**：`_PROJECT_ROOT` 基于 `__file__` 计算绝对路径，session 和 MCP 配置均基于此路径。

### 89. ToolRegistry 迭代 bug

**根因**：`ToolRegistry.__iter__` 返回 `iter(self._tools)`（dict 的 key 迭代）。`for name, tool in tool_registry` 把字符串 key（如 `"read"`）解包成单个字符 → `ValueError`。persona 有 `enabled_tools` 时必崩溃 → `ERR_INCOMPLETE_CHUNKED_ENCODING` → 前端显示 "network error"。

**修复**：`for name, tool in tool_registry._tools.items()`

### 90. 角色切换检测遗漏

**根因**：`_should_rebuild` 中 `persona_id is not None and current_pid != persona_id` — 当从 coder 切换到通用助手时 `persona_id=None`，第一个条件为 False，不重建。会话仍沿用 coder 的 7 个工具。

**修复**：`current_pid != persona_id` — `"coder" != None` 为 True，正确触发重建。

### 91. 切换会话白屏

**根因**：`Sidebar.tsx` `handleSwitch` 切换历史会话时未重置 chat store 流式状态。若上一会话有残留 `currentText`，`ChatContainer` 中 `showStreaming=true` → `hideLastBubble` 隐藏最后一条消息 → 白屏。

**修复**：`handleSwitch` 加载历史消息前调用 `cs.reset()` 清除所有旧状态。
