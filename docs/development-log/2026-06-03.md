## 详细记录

### 59-61. Bash 操作协议优化

参考 pi-mono 的 `BashOperations.exec(onData, signal)` 设计：
- `BashOperations.execute()` 增加 `on_data: Callable[[bytes], None]` 逐块推送
- `LocalBashOperations` 流式读取 stdout/stderr，每 4096 字节回调
- `signal: asyncio.Event` 传入，abort 时杀进程树（Linux: `kill(-pid, SIGKILL)`，macOS: `pkill -P` + `kill`）
- `start_new_session=True` 确保进程组隔离
- 超时后保留已捕获的部分输出，不再丢弃
- BashTool 集成 `truncate_head`（保留末尾，最新输出最有用）
- `commandPrefix`/`spawnHook` 支持沙箱环境初始化

### 62-64. 沙箱服务接入

- `SandboxQuota`: CPU/内存/磁盘/网络四维限制
- `SandboxBackend` Protocol: start/stop/health_check/restart 生命周期
- `DockerSandboxBackend`: 同时实现 SandboxBackend + FileOperations + BashOperations
  - 路径三区模型：`/mnt/output/`（读写）、`/tmp/`（临时）、系统目录（只读）
  - `docker run` 时注入 `--cpus`/`--memory`/`--network=none`
- `SandboxPolicyExtension`: 配额分配矩阵 + 危险命令正则拦截
- `SelfHealingExtension`: 即时修复（pip install）+ 增强错误提示

### 65. mutated_args + args_model

参考 pi-mono 的 "Mutate event.input in place" 设计：
- `on_before_tool_call` 可返回 `{"mutated_args": {...}}` 修改工具参数
- ExtensionRunner + _chain_before_hooks 均支持合并多个扩展的 mutated_args
- `ToolDefinition.args_model` 可指定 Pydantic 校验模型，tool_runner 在调用前自动校验

### 66-67. Agent 生命周期 hook

`BeforeAgentStart` hook 从 loop 移到 Agent._run()：
- 扩展可在 agent_loop 启动前注入 system_prompt 或前置 message
- loop.py 不再感知扩展存在，回归纯消息处理引擎

### 68-69. Agent 重构

参考 pi-mono Agent 设计：
- `pendingToolCalls: set[str]` 追踪执行中的工具调用
- `hasQueuedMessages()` 便捷查询
- `signal` property 公开 asyncio.Event
- `_handle_run_failure()` 创建结构化 AssistantMessage 并 emit AgentEnd
- `_create_loop_config()` 独立方法提取
- `AgentLoopConfig.provider` → `stream_fn` callable，loop 不依赖 provider 实例

### 70. ToolResultMessage tool_name 修复

**根因**：tool_runner.py 两处 `ToolResultMessage(...)` 构造漏传 `tool_name`。
实时 SSE 通过 `ToolExecutionEnd.tool_name` 正常，历史加载通过 `/session` API 返回 `"tool_name": null`，
前端 `loadMessages` 按 `tool_name` 匹配工具块失败 → 视频 block 不重建。

**修复**：两处补加 `tool_name=tool_call.name`。
