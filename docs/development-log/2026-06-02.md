## 详细记录

### 47. ToolResultMessage 持久化字段缺失

**根因**：`_persist_tool_result` 保存的 dict 缺少 `timestamp`，`ToolResultMessage` 模型缺少 `tool_name` 字段。
- 缺 `timestamp` → `deserialize_message` 校验失败 → `_restore_messages` 静默丢弃该消息
- 缺 `tool_name` → `model_dump()` 不输出 → 前端 `loadMessages` 无法按工具名匹配

**修复**：
- `messages.py`: `ToolResultMessage` 新增 `tool_name: str | None = None`，`timestamp: float = Field(default_factory=time.time)`
- `session.py`: `_persist_tool_result` 写入 `"timestamp": time.time()`

### 48. get_or_create 误销毁运行中的 assistant

**根因**：`/human-input` 端点调用 `get_or_create(session_id)` 未传 provider/model，旧逻辑将 `None` 与 assistant 创建时的 provider 比较，`None != "minimax"` → 销毁正在等待人工输入的助理 → `provide_human_input` 永远返回 false。

**修复**：抽取 `_should_rebuild` 静态方法，只在调用方**显式传入**不同参数时才触发重建。None 视为 wildcard（不比较）。

### 49. Agnes 视频生成工具

`agent_core/tools/agnes_video_tool.py`：
- API: `POST /v1/videos` 创建任务 → 轮询 `GET /v1/videos/{task_id}` 直到完成
- 参数：prompt、image/images、mode(keyframes)、width/height、num_frames(8n+1 ≤441)、frame_rate、seed
- 轮询：每 8s 查询，最长 300s，超时返回 task_id（不报错，防止重试循环）
- 进度：每 15s 通过 `ctx.on_update` 上报（sequential 模式下生效）
- Prompt 指引：明确告知模型不要重复调用、超时返回 task_id 供后续查询

### 50. 历史消息 widget 渲染

**修复前**：`loadMessages` 中 `tool_result` 匹配条件是 `blk.type === 'tool' && !blk.detail`，但 `parseAssistantMessage` 初始化 block 时 `detail` 已填 args JSON，条件永远不匹配。

**修复后**：改为反向遍历按 `label === tool_name` 匹配。对 `show_widget` 额外解析 `detail`（args JSON）提取 `html/title/height` 重建 widget block。

### 51. widget 重复渲染

**根因**：流式期间 `useSSE.processEvent` 中 `addWidget` 将 widget 存入 `widgets` 数组，同时 `blocksRef` 推送 widget block；`MessageBubble` 渲染 `BlocksRenderer`（含 widget block），又单独 `widgets.map` 渲染一次。`StreamingMessage` 同。

**修复**：删除 `MessageBubble.tsx:60` 和 `StreamingMessage.tsx:137` 两处 `widgets.map`，widget 仅通过 `BlocksRenderer` 内 block 渲染一次。

### 52. widget 格式对齐

### 55. 视频工具 API 字段修复 + 重试循环

**问题**：Agnes Video API 实际返回的视频 URL 在 `remixed_from_video_id` 字段，文档写的 `video_url` 不存在。导致工具轮询到 status=completed 后认为"未返回视频URL"。模型因超时/错误会自动重试，产生 3+ 个重复任务。

**修复**：
- 优先读取 `remixed_from_video_id`，兜底 `video_url`
- keyframes 模式校验：`mode=keyframes` 但未传 images → 立即拒绝，不创建任务
- prompt_guidelines 强化为"只调用一次，不重试"
- 超时消息从指令式（"直接告诉用户：..."）改为纯信息式

### 56. 视频工具改为快速轮询 + check_video_status

**问题**：工具内部轮询 180s，agent loop 阻塞，SSE 无事件，前端只知道"转圈"。本地 API 查询早已完成，但前端无法感知。

**修复**：
- `generate_video`：创建任务后只快查 30s（6s 间隔），完成则返回 URL，否则返回 task_id + 状态。工具 ≤40s 返回，不再阻塞
- 新增 `check_video_status` 工具：秒级查询任务进度，输出格式和 `generate_video` 一致
- `check_video_status` 注册到 chat_assistant，用户说"检查进度"即可触发

### 57. 前端视频播放器渲染

**设计原则**：后端只传结构化文本（URL + 分辨率 + 时长），前端解析 `.mp4` URL 渲染 `<video>` 播放器。`display` 字段不持久化，流式和历史走同一套解析逻辑。

**实现**：
- `MessageBlock` 新增 `video` 类型（videoUrl/videoSize/videoSeconds）
- `BlocksRenderer` 渲染 `<video controls preload="metadata">` + 分辨率/时长/下载链接
- `useSSE` tool_end：从 result text 正则提取 `.mp4` URL 创建 video block
- `chat-store.ts` loadMessages：`generate_video`/`check_video_status` 结果中提取 URL 重建 video block
- 两个工具输出相同格式文本，前端无需区分
